## 3. 必须遵守的工程约束

这些约束来自 `AGENTS.md` 和现有代码。违反任何一条，`npm run check` 或测试会失败，或者破坏已审核的发布物。

### 3.1 第四版参考源是冻结的

- `npm run check:reference`（`scripts/check-frontend-reference.mjs`）逐字节核对：`app/` 里的设计文件必须等于“`v4/` 对应文件 + 路径替换 + 适配脚本链”的结果。
- **不要修改** `v4/`、`v5/`、`src/`、`v2/`、`v3/`，也不要修改 `output/frontend-v4-2026-10-17/reference-sha256.json` 和 `output/v5-2026-10-17/v4-renamed-sha256.json`。
- `app/` 下的这些文件不能直接手改：`app.js`、`config.js`、`content.css`、`content.js`、`detail.css`、`detail.js`、`flows.css`、`index.html`、`journey.js`、`skill-task.js`、`styles.css`、`data.js`、`base.css`、`assets/folio-hero.png`。
- 对它们的任何改动，都要写成适配脚本里的 `once(原文, 新文)` 替换，然后让 `app/` 里的文件与替换结果一致。

### 3.2 新功能用独立文件加挂接

现有做法见 `scripts/online-apps-frontend-adaptations.mjs`（1.6 KB，是最好的模板）：

1. 新功能写在 `app/` 下的独立文件里。
2. 把文件路径加进 `scripts/frontend-functional-adaptations.mjs` 第 10 行的 `FUNCTIONAL_FILES`。不在这个列表里的文件出现在 `app/` 下，检查会报错。
3. 新建一个适配模块，用 `once()` 在 `v4/index.html` 和 `v4/app.js` 的文本上做挂接。锚点必须在文本中恰好出现一次。
4. 把新模块接到 `frontend-functional-adaptations.mjs` 第 22 行的调用链**最外层**。这样锚点可以直接从当前的 `app/app.js` 里复制。

### 第一阶段：首页（R1–R4）

**新增文件**

| 文件 | 内容 |
| --- | --- |
| `app/home.js` | 导出 `renderHome(ui, context)`，返回首页 HTML 字符串 |
| `app/refresh.css` | 本方案所有新增样式。在 `styles.css` 之后加载，用 `.v4` 前缀保持同等优先级 |
| `app/assets/book-light.webp` | 从 `prototype/` 复制 |
| `scripts/refresh-frontend-adaptations.mjs` | 导出 `withRefresh(source, text)` |

**挂接方式**

不要对 `home()` 那一行超长的模板字符串做多处子串替换，很脆弱。建议只用一个锚点，把函数改名并委托给新模块：

```js
// scripts/refresh-frontend-adaptations.mjs
export function withRefresh(source, text) {
  const once = (from, to) => { if (text.split(from).length !== 2) throw Error(`改版挂接锚点不唯一：${source}`); text = text.replace(from, to); };
  if (source === 'v4/index.html') once('  <title>', '  <link rel="stylesheet" href="/app/refresh.css">\n  <title>');
  if (source !== 'v4/app.js') return text;
  text = "import { renderHome } from './home.js';\n" + text;
  once('function home() {', 'function home() { return renderHome(catalogUI(), homeContext()); }\nfunction legacyHome() {');
  // homeContext() 的定义也在这里用 once() 追加，见下
  return text;
}
```

- 原来的 `home()` 函数体留在 `legacyHome()` 里不再调用，这样第四版文本保持完整。
- `catalogUI()`（`app/app.js:17`）已经把 `esc`、`icon`、`saveButton` 等工具函数打包好了，直接传给新模块。
- `homeContext()` 需要提供：`productStories`、`activeProduct`、`itemById`、`detailLink`、`all`（全部条目）。在适配脚本里用一个 `once()` 追加这个函数的定义。
- `index.html` 里已有多个样式表挂在 `'  <title>'` 这个锚点上。新模块在链的最外层，所以 `refresh.css` 会排在最后加载，这正是需要的顺序。

## 8. 风险与回退

| 风险 | 应对 |
| --- | --- |
| 适配锚点不唯一或失效 | 新模块放在调用链最外层，锚点从当前 `app/app.js` 复制；加测试 |
| 合并列表时同一工具出现两次 | 用 `contentIds` 去重，加测试 |
| 收藏键格式变化导致旧收藏丢失 | 不改现有键格式，只新增 `tools/<appId>` |
| 改 `service.mjs` 的停止逻辑影响后台类工具 | 只改浏览器类工具的分支；补测试 |
| 错误页改动破坏工具自己的接口 | 只对页面导航请求返回 HTML，其余保持 JSON |
| 没有 Docker，启动和停止无法实测 | 在记录里列明未验证项；不要写成已验证 |
| 新工具上架后没有分类 | 元数据覆盖测试；缺失时回退到“其他” |

回退：每个阶段单独提交。回退某个阶段时，还原该阶段的提交即可；第一、二阶段只涉及前端文件和适配脚本，不涉及数据和存储结构。第四阶段新增的接口字段是只增不改，旧前端不受影响。

## 附录 C：重新生成浅色主视觉

只有需要调整抠图时才用。依赖 `numpy`、`scipy`、`opencv-python-headless`、`Pillow`，**装在仓库之外的临时环境里**，不要加进项目依赖。

```
python3 tools/make-book-light.py <仓库>/app/assets/folio-hero.png book-light.webp 0.55
```

- 第三个参数是暗部提亮的强度，0.55 是当前使用的值。
- 脚本里的多边形坐标是对着这张原图手工描的，换图后不适用。
- 输出是带透明通道的 WebP，投影已经合成在图里，页面上不需要再加阴影。
