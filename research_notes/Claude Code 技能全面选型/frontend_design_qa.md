## Q1. Which design skills are rated best head-to-head, and which installed ones overlap (what to keep)?

### Takeaway
No independent benchmark is authoritative. Third-party tests disagree, but the most common verdict is: anthropics `frontend-design` as the light default for new UI, pbakaus `impeccable` as the strongest for auditing and polishing existing UI (one test scored it 92 vs 64), and `ui-ux-pro-max` as a lookup database whose own output reads as generic. The installed set has a lot of overlap and it is out of date. Upstream taste-skill 2.5 has absorbed `redesign-skill`, dropped `output-skill`, and moved soft, minimalist and brutalist into a separate "classics" repo where they are opt-in only. Recommended core: `impeccable` + `frontend-design` (+ `ui-ux-pro-max` for data lookups only). Pick one of taste-skill 2.5 or impeccable as the "opinionated builder", not both, and remove the `design` skill (it calls paid image APIs) and `output-skill`.

### Inferences
- **Redundancy map of what is installed:**
  - `taste-skill` (old 2.1.x copy) + `soft-skill` + `minimalist-skill` + `brutalist-skill` + `redesign-skill` are one family. Upstream has merged redesign into taste-skill and deprecated the others to opt-in. Keeping soft, minimalist and brutalist as auto-triggerable skills is now contrary to the author's own guidance. Keep them only if you want explicit `/soft-skill`-style style presets.
  - `output-skill` (full-output-enforcement) has been removed upstream. Its "never truncate" instructions are a forceful prompt override. **Remove it.**
  - `ui-styling` (shadcn+Tailwind) overlaps with the official `shadcn` skill (shadcn-ui/ui), which is CLI-grounded. `design-system` overlaps with impeccable `init/document/extract` (DESIGN.md) and Stitch `design-md`. `design` overlaps with nothing core and is risky because of the paid APIs.
  - `frontend-design` and `impeccable` overlap in "aesthetic direction", but they complement each other: frontend-design is a short prompt for greenfield work, and impeccable is a command suite for critique, audit and polish.
- **Recommended keep set for a Chinese-speaking web-app builder in ephemeral cloud containers:** `impeccable` (update to 4.9.x), `frontend-design`, `ui-ux-pro-max` (lookups only, keep the data), and the official `shadcn` skill (replacing `ui-styling`). Optionally add taste-skill 2.5.1 *instead of* the old taste family, and only if marketing or company landing pages are the main output, because 2.5 is very opinionated toward "company website" layouts and adds a Stop-hook gate. Remove: `output-skill`, `redesign-skill` (merged upstream), `design` (paid APIs), and probably soft, minimalist and brutalist.
- Running taste-skill 2.5 and impeccable together risks conflicting directives, since both claim "design, redesign, polish, review".

## Q3. Best accessibility and web-performance audit skills?

### Takeaway

## Q4. Best browser-automation/E2E/QA skills for a headless Linux cloud container (Chromium preinstalled at /opt/pw-browsers)?

### Takeaway
The best fit is Microsoft `playwright-cli` (official, Playwright-native, so it should reuse the `/opt/pw-browsers` Chromium) and Vercel `agent-browser` (the most token-efficient; point `AGENT_BROWSER_EXECUTABLE_PATH` at the preinstalled Chromium to skip the Chrome-for-Testing download). Keep the installed anthropics `webapp-testing` (Python Playwright) as the zero-install fallback. Avoid browser-use's `qa` skill (mandatory paid cloud browsers) and Browserbase remote mode (API key).

### Cited Findings
- **Token benchmark (one blog, 10-step task):** Playwright MCP about 114K tokens, DevTools MCP about 50K, Playwright CLI about 27K, agent-browser about 7K — [ytyng.com benchmark](https://www.ytyng.com/en/blog/ai-browser-automation-tools-comparison-2026); [dev.to agent-browser token article](https://dev.to/chen_zhang_bac430bc7f6b95/why-vercels-agent-browser-is-winning-the-token-efficiency-war-for-ai-browser-automation-4p87). A competing vendor benchmark (Browser Use, which has a stake in the result) reports agent-browser 3.3M median input tokens, Playwright MCP 4.4M, Chrome DevTools MCP 6.7M and its own Browser Harness 2.1M, with score differences "within noise" — [browser-use.com](https://browser-use.com/posts/best-mcp-servers-to-control-a-browser)
- "Pick agent-browser for the fastest Chrome-only loop… Pick Playwright CLI when you need Firefox and WebKit coverage, Playwright traces, or your team already runs on Playwright" — [test-lab.ai](https://www.test-lab.ai/blog/agent-browser-vs-playwright-cli)
- **playwright-cli**: official Microsoft. The skill covers test generation, `npx playwright` tests, tracing, video and request mocking — [microsoft/playwright-cli](https://github.com/microsoft/playwright-cli). Octomind found CLI and MCP returned identical snapshots (about 12.3K tokens each), so the savings come from schema overhead — [octomind.run](https://octomind.run/blog/playwright-mcp-vs-cli)
- **agent-browser**: install with `npm i -g agent-browser && agent-browser install` (downloads Chrome for Testing). Linux: `agent-browser install --with-deps`. Native binaries for Linux x64/ARM64 glibc and musl. The README documents `--executable-path` / `AGENT_BROWSER_EXECUTABLE_PATH`, `AGENT_BROWSER_NO_XVFB` and a version-check env var. The `dogfood` QA skill is under `skill-data/dogfood` — [vercel-labs/agent-browser](https://github.com/vercel-labs/agent-browser)
- **dev-browser** (`SawyerHood/dev-browser`, MIT, last commit 2026-11-03): one skill, `skills/dev-browser/SKILL.md` ("persistent named pages via the dev-browser CLI"). Install with `npm install -g dev-browser`. "The first run downloads the binary if the install script was blocked". `dev-browser install` runs "only if… 'No Chrome found'". Env vars include `DEV_BROWSER_CHROME`, `DEV_BROWSER_DOWNLOAD_BASE` and `DEV_BROWSER_SKIP_DOWNLOAD` — [SawyerHood/dev-browser](https://github.com/SawyerHood/dev-browser). ### Inferences
- In the cloud container: setting `PLAYWRIGHT_BROWSERS_PATH=/opt/pw-browsers` should let playwright-cli and webapp-testing reuse the preinstalled Chromium, provided the Playwright version matches the browser build. For agent-browser and dev-browser, point `AGENT_BROWSER_EXECUTABLE_PATH` / `DEV_BROWSER_CHROME` at `/opt/pw-browsers/chromium-*/chrome-linux/chrome` to avoid the downloads, which may be blocked by the sandbox proxy. Not tested this session.
- dev-browser and impeccable both fetch binaries from GitHub releases at first run, and taste-skill fetches fonts and photos. In a restricted-network container these can fail, so check that the domains are allowed.
- **Suggested testing stack**: `playwright-cli` (E2E + test generation + traces) + `agent-browser` with `dogfood` (cheap exploratory QA + screenshot self-review) + `webapp-testing` (already installed) + `antfu/skills` vitest + petrkindlmann `visual-testing` (pick individual skills, not all 50).
