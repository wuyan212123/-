# SP 广告工作台 · 前台改版开发文档

本目录是交给 Codex（或其他开发者）的实施文档，依据高保真原型 v7（`prototype/sp-workbench.html`，2026-10-27）编写，目标是把原型中的信息架构、页面、交互和分析规则落地到现有的 SP 广告工作台。

## 1. 这次要做什么

现有程序：`3.0.0-alpha.3` 本地工作台。前端 React + TypeScript，图表 Recharts，图标 Lucide；后端 FastAPI；存储本地 SQLite；默认地址 `http://127.0.0.1:8001/`。

| 类别 | 内容 |
| --- | --- |
| 保留 | 已验证的数据口径、原始文件与来源行号、项目、用户业务记录、导入流程、Excel 导出、规则配置、可选 AI 配置 |
| 重做 | 导航与页面组合、顶部分析范围条、经营总览、关键词决策页（表格 + 详情 + 来源活动展开）、复盘报告的结构与呈现、三种宽度的布局 |
| 新增（需评审，见 `08`） | 周期优化工作流（收割 / 否定 / 调价 / 批量表 / 动作日志）、复盘分析四个维度、规则生成的“本期结论”与变化拆解、关键词“变动”维度、人工判断记录、报告 12 章节框架、⌘K 命令面板 |
| 不做 | 广告账户同步、向亚马逊提交调价或否词、云端多用户与权限、库存利润联动、PDF 输出 |

## 3. 原型怎么用

- 直接用浏览器打开 `prototype/sp-workbench.standalone.html`，不需要服务。左下角「状态演示」可切换 12 种状态（无项目、空项目、无基准、读取失败、导入待确认等）。
- 原型是单文件原生 JS，结构如下，文档中写作 `函数名()` 的都能在源码里搜到：

| 原型中的名字 | 作用 |
| --- | --- |
| `S` | 全部界面状态 |
| `render()` | 整页重绘（正式实现改为 React 组件） |
| `ACT` | 所有点击交互，键名即 `data-act` |
| `calc(scope)` | 分析主入口：按范围汇总出 A/B 指标、关键词、标签、建议 |
| `tagsOf()` `suggestOf()` `mvOf()` `decompAB()` `trendOf()` `cycleData()` `prevCycle()` `repBuild()` | 判断规则的参考实现 |
| `gen()` | 合成数据生成器，**只用于原型**，不要带进正式代码 |

- 文档与原型冲突时，以本文档的口径章节为准，并在 PR 里指出冲突点。
- 原型里的数字全部是合成数据，不代表任何真实业务结论。

## 4. 硬性约束

任何实现都不能违反以下八条，验收时逐条检查：

1. **比率重算**：CTR、CVR、CPC、ACOS、ROAS、CPA 一律由汇总后的基础量重算，不平均逐日或逐行比率；分母为 0 显示“—”（不可计算）。
2. **缺日不补零**：A/B 天数不同时，花费、销售额、订单、曝光、点击按已覆盖天数取日均后再比较；比率直接比较。
3. **单一来源**：一次 A/B 对比只用一种来源（搜索词报表或投放报表），两者不能相加。
4. **两层控制**：分析范围（项目、来源、A/B、维度筛选）决定数据；清单视图（视图、变动、标签、搜索、订单、排序、分页、显示列、列宽）只改变屏幕显示，不影响分析、报告与 Excel 导出。
5. **旧结果保护**：范围请求进行中或失败时，界面保留并标明上次成功的结果（`shown`），禁止导出与生成报告。
6. **不执行广告改动**：工具只生成建议、清单、批量操作表和报告。按钮文案用“导出”“标记”“查看建议”，不能用“执行”“应用到广告”。
7. **颜色按指标含义**：销售额、订单、CTR、CVR、ROAS 上升为好；ACOS、CPC、CPA 上升为坏；花费、曝光、点击的涨跌为中性灰。
8. **AI 可选**：不配置 AI 时，所有分析、建议和报告完整可用；“已保存配置”不等于“连接已验证”。

## 5. 术语

| 术语 | 含义 |
| --- | --- |
| 项目 | 一个产品（站点 + ASIN），拥有自己的报表、规则、报告 |
| 来源 | `term` 搜索词报表 / `target` 投放报表 |
| A 期 / B 期 | 本次分析期 / 对比基准，日期首尾均计入 |
| 分析范围 `scope` | 项目、来源、A、B、维度筛选（活动、广告组、匹配、投放包含、精确搜索词） |
| 已显示范围 `shown` | 当前屏幕上结果所对应的范围；请求成功后才等于 `scope` |
| 关键词（key） | 搜索词报表下是消费者搜索词，投放报表下是投放词或投放对象 |
| 来源活动行（row） | 关键词在某个 活动 × 广告组 × 投放 × 匹配 下的明细 |
| 投放组 | 活动 × 广告组 × 投放 × 匹配 的汇总，是调价的对象 |
| 覆盖 | 某范围内有数据的天数 / 总天数，以及缺日列表 |
| 标签 | 规则给出的状态标记（风险 / 机会 / 提升 / 需核查） |
| 建议 | 按来源活动行给出的动作，带事实、命中条件、风险和优先级 |
| 人工判断 | 运营对建议的“已采纳 / 暂不处理”记录，写入本期复盘 |
| 变动 | 关键词 A 对比 B 的 新增 / 增长 / 下滑 / 消失 / 稳定 |
| 周期 | 每周一轮的优化：准备与回看 → 诊断 → 收割 → 否定 → 调价 → 确认导出 |
| 动作日志 | 一个周期中确认导出的动作清单，下期用来回看效果 |
| 归因滞后 | SP 报表按点击后 7 天归因，最近几天的订单还会补入 |

```text

prevCycle()、repBuild() 是计算规则的参考实现。

要求：
1. 先读 docs/dev/README.md 的“硬性约束”和 02-metrics-and-rules.md，再读仓库现有的 AGENTS.md、README.md、
   docs/REBUILD.md 等文件，确认现有接口与数据口径；文档与现有已验证口径冲突时，以现有口径为准并在 PR 中说明。

5. 遇到 08 中“待决问题”列出的事项，先按文档给出的默认方案实现，并在 PR 描述中标注。
```
