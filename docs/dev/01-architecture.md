### 1.3 运营的主路径

```text
看（总览 KPI 与本期结论）→ 找（待处理队列 / 变动筛选，带条件进入关键词清单）
→ 证（详情侧栏：建议与依据、A/B 指标、近 12 周、来源活动）→ 做（周期优化：收割 / 否定 / 调价，导出批量表）
→ 记（复盘报告：结论、原因、下期动作、负责人与复查日）→ 下周回看（上期动作复盘）
```

所有跳转都保留当前分析范围；跳到关键词页时可携带清单视图条件（视图、标签、变动、排序）。

## 3. 全局状态模型

原型把所有状态放在一个对象 `S` 中。正式实现建议按下表拆分（沿用现有状态管理方案；若现有代码没有统一方案，推荐 Zustand 或 React Context + reducer）。

### 3.1 分析范围与结果

```ts
type Source = 'term' | 'target';
type MatchType = 'auto' | 'broad' | 'phrase' | 'exact' | 'asin';
interface DateRange { s: string; e: string }            // YYYY-MM-DD，首尾都计入
interface ScopeFilters {
  campaigns: string[]; adgroups: string[]; match: MatchType[];
  target: string;      // 投放包含（子串，不区分大小写）
  term: string;        // 精确搜索词（完整匹配，小写比较）
}
interface Scope { source: Source; A: DateRange; B: DateRange; f: ScopeFilters }

interface ScopeState {
  projectId: string;
  scope: Scope;          // 控件上正在编辑 / 已应用的范围
  shown: Scope;          // 屏幕上结果对应的范围（最近一次成功请求）
  loading: boolean;      // 正在请求 scope
  error: string | null;  // 最近一次请求失败的原因
  updatedAt: string;     // 最近一次成功时间 HH:MM
}
```

规则：

1. 日期、来源、筛选都在弹层里编辑草稿，点“应用”后才写入 `scope` 并发起请求（来源切换按钮除外，点即生效）。
2. `scope !== shown` 时，对应控件右上角显示黄点（pending）；状态胶囊显示“正在更新…”。
3. 请求成功：`shown = scope`，`updatedAt` 更新，清单回到第 1 页，关闭详情与行展开。
4. 请求失败：保留 `shown` 和旧结果，横幅写明实际显示的范围，提供“恢复为显示范围”（`scope = shown`）与“重试”。
5. `loading || error` 时，导出 Excel、导出批量表、生成报告按钮禁用。
6. 切换项目：清空维度筛选，按新项目的数据截至日重设为“最近 7 天 vs 前 7 天”，保留来源；同时重置清单视图（保留每页条数与变动依据）、周期选择、详情、行展开。
7. 默认范围：A = 截至日往前 7 天（含截至日），B = A 之前 7 天，来源 = 搜索词报表。

### 3.2 清单视图（只影响关键词页显示）

```ts
interface ListView {
  view: 'all' | 'risk' | 'opp' | 'chg' | 'check' | 'done';
  mv: 'all' | 'new' | 'up' | 'down' | 'lost' | 'flat';
  mvBy: 'sales' | 'orders' | 'clicks' | 'spend';
  tag: string;           // 'all' | 标签名 | 'sg:转 Exact'
  q: string;             // 搜索：关键词包含 或 任一活动名包含
  orders: 'all' | 'with' | 'without';
  sort: { k: string; d: 1 | -1 };   // k 为列 id，默认 A_spend 降序
  page: number; size: 20 | 50 | 100;
}
```

切换视图、标签、变动、搜索、订单、每页条数时回到第 1 页。

## 4. 前后端分工

**计算放后端，展示与清单视图放前端。** 原型为了单文件演示把计算放在浏览器里，正式版应把 `02-metrics-and-rules.md` 的全部规则实现为后端（Python）的纯函数，并配单元测试。

| 层 | 负责 |
| --- | --- |
| 后端 | 导入与归档、按范围汇总（A/B 指标、覆盖）、关键词聚合与来源活动行、标签、建议、变动、拆解、12 周序列、结构指标、周期候选（收割 / 否定 / 调价）、动作日志与上期回看、报告章节数据、Excel / 批量表 / Markdown 导出 |
| 前端 | 范围编辑与请求状态、清单视图的过滤 / 排序 / 分页（数据量为数百到数千个词，前端处理即可）、列偏好、图表绘制、详情与展开、报告排版、运营补充与负责人编辑 |

数据量参考：真实验证数据 7,140 条明细、108 天跨度，单个范围通常数百个词。关键词列表一次返回全部（含来源活动行），无需服务端分页；如超过 5,000 个词再考虑分页。


## 6. 建议的后端组织

```text
analysis/
  scope.py        范围解析、覆盖计算、日均换算
  metrics.py      基础量汇总与 derive()
  keywords.py     关键词聚合、kwType、标签 tagsOf、建议 suggestOf
  movement.py     mvOf、kwMoves（含主因）
  decompose.py    LMDI 拆解 decompAB
  weekly.py       12 周区间、活动 / 关键词周序列、trendOf、streak
  structure.py    匹配方式、品牌 / 非品牌、无效花费率、同词多活动、星期规律、集中度
  cycle.py        收割、否定、调价、影响估算、批量表行、动作日志、上期回看
  report.py       报告上下文与 12 个章节的数据与文案
exports/          Excel、批量操作表（xlsx）、动作日志（csv）、Markdown
```

每个模块的函数都应是“输入范围数据 + 规则 → 输出结构化结果”的纯函数，便于用固定数据做回归测试（见 `08` 的测试计划）。
