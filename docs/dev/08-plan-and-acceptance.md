## 4. 测试计划

### 4.1 后端单元测试（每条规则一组）

| 模块 | 必测用例 |
| --- | --- |
| derive / 空值 | 分母为 0 返回 None；比率由汇总重算（两行 ACOS 平均 ≠ 汇总 ACOS 的反例） |
| 覆盖与日均 | 缺日不补零；A 7 天 B 6 天时量类按日均；首尾日都计入 |
| 标签 | 每个标签恰好在阈值上 / 下；新品模式放宽；无 B 时不出现对比类标签；活动分化两种情形 |
| 建议 | 四条规则的优先顺序；品牌词改为人工复核；转 Exact 只在没有 exact 行时出现 |
| 变动 | 新增 / 消失；±20% 边界；最小差额（销售额 19.99 与 20）；日均比较 |
| 拆解 | 三种拆法贡献之和 = 总变化；有 0 因素返回 None；A=B 时 L 取 tA |
| 趋势 | `trendOf()` 每个分支；`streak()` 的 2% 容差与遇空停止 |
| 结构 | 无效花费率按明细行判断；同词多活动的保留行；星期规律异常日排除 |
| 周期 | 收割出价夹在 CPC 的 0.9–1.6 倍；否定的点击 / 花费双条件；调价六类分桶与降幅上限；影响估算；批量表行；上期回看相对整体的判断 |
| 报告 | 结论句各分支；关键判断的选取（2 问题 + 1 亮点）；各章节无 B / 投放报表时的文字 |

### 4.2 对照测试（用原型做参考实现）

原型的计算函数可以直接当作“标准答案”。做法：

1. 用 Playwright 打开 `prototype/sp-workbench.standalone.html`。原型脚本是一个立即执行函数，测试前在副本中把结尾的 `})();` 替换为暴露函数的代码，例如：

```js
window.__t = {
  R: () => calc(S.shown),
  cycle: () => { const c = cycleData(calc(S.shown)); return { h: c.harvest.length, n: c.neg.length, im: cycImpact(c) }; },
  report: () => reportMd(calc(S.shown)),
  rows: () => pdata(proj()).rows.map(r => ({ id: r.id, term: r.term, camp: r.camp, ag: r.ag, target: r.target, match: r.match,
    daily: Object.fromEntries(['impr','clicks','orders','spend','sales'].map(k => [k, Array.from({length: N}, (_, t) => r.F[k][t+1] - r.F[k][t])])) })),
  days: () => Array.from({length: N}, (_, t) => ds(t)),   // 第 t 天的日期，2026-07-10 起共 108 天
  miss: () => [...pdata(proj()).miss].map(ds)            // 缺日（这些天 daily 全为 0，导入夹具时应视为“无数据”而不是 0）
};
})();
```

2. 用 `__t.rows()`、`__t.days()`、`__t.miss()` 导出合成明细（258 行 × 108 天，含 2 个缺日），作为后端测试夹具导入。原型中搜索词报表与投放报表共用同一批合成行，导入时两种来源各导一份即可。
3. 用同一夹具调用后端接口，与 `__t.R()`、`__t.cycle()`、`__t.report()` 的结果逐项比较。`02` 第 15 节列出了默认状态下的部分参考值。
