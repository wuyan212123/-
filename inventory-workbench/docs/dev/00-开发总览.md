# 进销存协作工作台 · 正式开发文档（总览）

> 读者：负责后续开发的编码代理（Codex）与开发者。
> 依据版本：原型第六版（分支 `claude/friendly-wozniak-y4lsto`，提交 `5ea6034` 之后）。
> 目标：在正式工程里**一比一还原**原型的界面与交互，再逐步把演示逻辑替换为真实数据与后端。

## 1. 一句话说明

原型是一个单文件、无框架的前端（`inventory-workbench/index.html`，由 `src/` 拼接构建），用固定种子生成的**虚构演示数据**，完整演示了跨境电商（亚马逊七个站点）的进销存协作：国家主表、SKU 统一详情、运营人员视图、全局搜索、总销量、库存汇总、发货计划、数据更新与异常、版本记录、原表覆盖与验收。界面为简体中文，采用 macOS 系统风格，支持浅色和深色。

**原型就是规格。** 文档描述原型“是什么、为什么”；遇到文档与原型不一致时，以原型的实际行为为准，并在 PR 里指出文档需要更正。

## 3. 范围

**必须一比一还原（第一阶段，前端，用演示数据）**
- 外壳：侧栏（可收起）、统一工具栏（标题、全局搜索、演示身份、显示说明、密度、主题）、底部来源日期条、未保存提示条、通知、弹层。
- 全部页面与弹层（见 03 两份页面规格），含列配置、年份多选、色阶、趋势小图、逐年对比图、可撑天数、库存推演、批次时间线、库龄构成。
- 全部交互行为（见 06），含返回时恢复列表状态、焦点恢复、输入法保护、键盘操作。
- 浅色/深色、舒适/紧凑、简洁模式（ⓘ 显示说明）、1440 / 1024 / 768 / 390 / 320 宽度。

**第二阶段（接真实数据与后端）**：见 05 接口契约与 08 任务清单。登录与权限、保存与冲突、导入流程、版本快照、团队级列配置都在这一阶段，前端界面不变。

**不在范围**：采购计算与下单（原型只展示采购在途）、任何未经业务确认的公式（见 04-待确认项）。

## 4. 不可违反的原则

1. **界面一比一**：原样复用 `src/styles.css`（令牌、类名、选择器），DOM 结构与类名与原型一致。用 `tools/visual.cjs compare` 对比，每个状态不同像素 ≤ 0.5%。
2. **数据语义不混**：缺报“未提供”、源表“无字段”、期间“未发生”、源表“空白”、原公式“待接入”、真实 0 必须分开显示（见 04 第 2 节）。不得把缺失显示成 0，也不得把 0 显示成缺失。
3. **不补造公式**：原型里只有 US 的箱数 `J=HT/I` 与补货后可售天数 `HX=(HS+HT)/(HO/7)` 有局部证据。其余计算一律显示源值或“待接入”。“可撑天数 / 库存推演 / 预计到仓日”是**演示估算**，界面上必须保留“演示估算，非原公式”的标注，直到业务确认（04-待确认项 #20）。
4. **演示与真实分开**：演示数据、演示身份、模拟保存都要有明确标识。接入真实数据后，才能去掉对应标识，不能提前去掉。
5. **不联系外部服务、不上传真实业务文件、不写生产数据**（原型阶段的约束，第二阶段改由后端与权限保证）。
6. **每个 PR 都要过验收**：行为检查、视觉对比、axe 无障碍 0 违规、性能不劣于预算（见 07）。

## 5. 交付物与完成标准（Definition of Done）

一个页面或功能“完成”的条件：
- [ ] 视觉：`node tools/visual.cjs compare <新实现URL> --only <该页状态>` 全部通过（≤ 0.5%），浅色、深色、手机三种变体都通过。
- [ ] 行为：`docs/03-功能覆盖与验证记录.md` 第 4 节中与该页相关的检查，已改写为新工程的端到端测试并通过。
- [ ] 无障碍：axe 扫描该页（浅色、深色）0 违规。
- [ ] 性能：按 `?scale=25` 规模，渲染耗时不超过 07 文档的预算。
- [ ] 文案：与原型逐字一致（标点、空格、全角/半角都一致）。
- [ ] 没有引入未经确认的业务公式；演示估算的标注仍在。

## 6. 原型快速上手

```bash
cd inventory-workbench
python3 tools/build.py                       # src/ → index.html、dist/workbench.html
open index.html                              # 直接用浏览器打开，无需服务器
open "index.html?scale=25"                   # 真实数据量（约 550 SKU、2,600 Listing）
node tools/verify.cjs                        # 143 项交互检查（需 playwright）
node tools/visual.cjs compare <URL>          # 与新实现逐像素对比
node tools/perf.cjs 25                       # 性能
npm i axe-core && node tools/a11y.cjs        # 无障碍
```

浏览器控制台里可以直接调用原型的全局对象来查看任何状态：`S`（全局状态）、`D`（演示数据）、`go('stock')`、`openSku(pid, {country:'US'})`、`wbTest.states()`、`wbTest.open('detail-plan')`。
