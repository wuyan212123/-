> 读者：在新工程（建议 React + TypeScript）里一比一还原原型行为的编码代理。
> 依据：`src/app-core.js`、`src/app-main.js`、`src/app-cols.js`、`src/app-cover.js`、`src/app-viz.js`，并对照 `src/app-country.js`、`src/app-detail.js`、`src/app-pages.js`、`src/shell.html`、`src/data.js` 中触发控件的写法。所有结论均来自源码；源码里看得出但可能是无意为之的行为，单列在“附录 A 源码怪癖”，由业务决定是否保留。

## 0. 前置事实

### 0.1 脚本加载顺序（决定 `ACT`/`INP` 合并结果）

`tools/build.py` 按以下顺序把脚本拼成一个 `<script>`：

`data.js → app-core.js → app-country.js → app-viz.js → app-cols.js → app-cover.js → app-detail.js → app-pages.js → app-main.js`

- `app-core.js` 定义全局 `S`、`ACT_EXTRA = {}`、`INP_EXTRA = {}`、`PAGES = {}`。
- `app-country.js`、`app-cols.js`、`app-cover.js`、`app-pages.js` 往 `ACT_EXTRA`/`INP_EXTRA` 里 `Object.assign` 追加处理函数，并往 `PAGES` 注册页面函数。
- `app-cols.js` 在加载时给 `S` 追加 `S.colcfg`、`S.tpls`（从 localStorage 读取并校验）。
- `app-main.js` 定义 `ACT`、`INP`，最后执行 `Object.assign(ACT, ACT_EXTRA); Object.assign(INP, INP_EXTRA);`，再调用 `boot()`。键名无重复，合并无覆盖。
- 工作区中 `tools/build.py` 已在 `app-main.js` 之后追加 `app-test.js`（测试钩子 `window.wbTest`，直接写 `S` 后调用 `go()` 等把页面置于指定状态，见 07 号文档）。它不增删 `ACT`/`INP`，不影响本文描述的交互；新实现需按 07 号文档提供同名钩子。

### 1.6 分页状态 `pstate(scope)`

```js
function pstate(sc) {
  if (sc === 'country') return cui(S.country);
  if (['people', 'search', 'total'].includes(sc)) return S[sc];
  return S.tp[sc] || (S.tp[sc] = { page: 1, size: 25 });
}
```

| scope | 状态对象 | 默认 size | 每页选项 | 使用位置 |
| --- | --- | --- | --- | --- |
| `country` | `cui(S.country)`（每国一份） | 12 | 8 / 12 / 25 / 50 | 国家页 overview/month/week/future/plan/stock/info 视图的主表（batch 视图不显示主分页） |
| `people` | `S.people` | 12 | 8 / 12 / 25 / 50 | 人员视图 |
| `search` | `S.search` | 8 | 8 / 12 / 25 | 搜索结果 |
| `total` | `S.total`（四个 tab 共用一个页码） | 8 | 8 / 12 / 25 | 总销量 |
| `plan` | `S.tp.plan` | 25 | 25 / 50 / 100 | 发货计划页（SKU 行） |
| `batch-<cc>` | `S.tp['batch-US']` 等 | 25 | 25 / 50 / 100 | 国家页批次视图下方“按 Listing 的批次明细” |
| `st-total`、`st-aesa`、`st-dom`、`st-domraw`、`st-fba`、`st-aging`、`st-awd` | `S.tp[...]` | 25 | 25 / 50 / 100 | 库存汇总各 tab 的表 |
| `rec-<记录表id>` | `S.tp[...]` | 25 | 25 / 50 / 100 | 更新页“过程记录”各表（id 见 `PROC`：status、issues、ledger、shiphist、batchupd、rcvex、rcvrec、weekly、variant、formula、newsku、datebase、accept、files） |

规则：

1. **页码越界收敛**：每次渲染（`pagedTable` 或页面函数内）计算 `pages = max(1, ceil(total/size))`，若 `page > pages` 则把 `page` 写回为 `pages`（写入状态，不只是显示）。
2. **分页器**（`pager()`）：显示“共 N 条”、每页下拉（`id="ps-<scope>"`、`data-in="pagesize"`）、上一页 / 下一页按钮（`data-act="page" data-p="page±1"`，到头时 `disabled`）、“第 x / y 页”。
3. **改每页条数**：`size = Number(value); page = 1`。
4. **筛选变化重置为第 1 页**：`cq/cowner/cgrade/clabel/cissue/cclear`（国家）、`person/pcountry/pstatus/pcell`（人员）、`smode/smultigo/sclearq/sclearf/try/sq/scountry/sowner`（搜索）、`tq/towner`（总销量）、`plq/plonly/plcountry/plstatus`（发货计划 `S.tp.plan.page = 1`）、`popall`。
5. **不重置页码**：排序（`sort`）、国家视图切换（`cview`）、总销量 tab（`ttab`/`tblk`）、库存汇总 tab（`stab`）、国家切换（新国家保留自己的页码）。
6. `S.tp` 的键各自独立、整个会话内保留（离开页面再回来仍是原页码）。

### 1.7 不在 `S` 中的模块级可变状态

| 变量 | 位置 | 作用 | React 中建议 |
| --- | --- | --- | --- |
| `modalReturn` | core | 打开弹层前的焦点元素，关闭后归还 | 弹层组件内 `useRef` 保存 `document.activeElement` |

| `COVER_MEMO` | cover | 可撑天数缓存，签名 = `baseDate\|fba\|avg4\|transitSel` | `useMemo`/选择器缓存 |

## 2. 渲染模型

原型是“状态对象 + 模板字符串 + innerHTML”的模型：所有交互先改 `S`，再选一种重绘方式。下表是 5 种重绘方式，后文动作字典的“重绘方式”列引用这些代号。

| 代号 | 函数 | 作用范围 | 页面滚动 | 表格内滚动 | 焦点 |
| --- | --- | --- | --- | --- | --- |
| **R-top** | `render({ top: true })` | 侧栏、工具栏状态、来源条、`#main`、未保存条 | 置顶 `main.scrollTop = 0` | 丢失 | 由调用方处理（`go()`/`openSku()` 会把焦点给 `#main`） |
| **R** | `render()` | 同上 | 不主动设置（`#main` 内容被替换，浏览器按新内容高度钳制；`goBack` 随后在 rAF 中手动恢复） | 丢失 | 丢失 |
| **RK** | `rerenderKeep()` | 同 `render()` | 恢复 | 恢复（所有带 id 的 `.tbl-wrap`） | 按签名恢复 |
| **局部** | `refreshPlanDerived` / `setDerived` / `renderSavebar` / `renderColCfg` / `#cc-groups` / `showPop` / 单图重画 | 只改指定节点 | 不动 | 不动 | 不动（正在输入的控件不被替换） |
| **壳** | `renderSidebar()` 和/或 `renderToolbarState()` | 侧栏 / 工具栏属性、根 class | 不动 | 不动 | 侧栏重写时侧栏内焦点丢失 |

### 2.1 `render(opts)`

```text
render(opts):
  renderSidebar()          // 侧栏整块重写；当前项：详情页时取 S.detail.from.page（缺省 'country'）
  renderToolbarState()     // 标题/副标题、主题与密度按钮、根元素 data-theme、body class
  renderSrcbar()           // 底部来源条（含浏览器“今天”日期）
  #main.innerHTML = (PAGES[S.page] || PAGES.country)()
  renderSavebar()
  if opts.top: #main.scrollTop = 0
  afterRender()
```

`renderToolbarState()` 的副作用（每次 render 都执行）：

- `#role.value = S.role`。
- 标题：详情页为商品 SKU，副标题 `SKU 统一详情 · 来自 {from.label | '国家主表'}`；国家页副标题 `{国家名} {cc} · {视图名} · 演示数据`；其余页 `进销存协作工作台 · 演示数据`。
- 主题按钮：图标 `auto/sun/moon`，`title = 主题：xx（点击切换）`，`aria-label = 主题：xx，点击切换`。
- 密度按钮：`title/aria-label` = `密度：紧凑（点击切换为舒适）` 或 `密度：舒适（点击切换为紧凑）`。
- `<html>`：`theme === 'system'` 时移除 `data-theme` 属性，否则设为 `light`/`dark`。
- `<body>`：`density-compact`（紧凑时）、`show-info`（显示说明时）。
- `#infoBtn`：`aria-pressed`、`title/aria-label` = `隐藏说明与字段来源` / `显示说明与字段来源`。
- `#app`：class `collapsed`、`expanded`。

### 2.2 `rerenderKeep()`：保持滚动与焦点的重绘（逐步）

```text
1. st  = #main.scrollTop
2. sc  = captureTables()        // 所有 .tbl-wrap[id] → [scrollLeft, scrollTop]
3. sig = focusSig(document.activeElement)
4. render()                      // 不带 top
5. #main.scrollTop = st
6. restoreTables(sc)             // 按 id 找回同一表格容器并恢复两个方向的滚动
7. el = sig && document.querySelector(sig)
8. 若 el 存在但已 disabled（如翻到最后一页后“下一页”被禁用）：
     el = el.closest('.pager, .row, .detail-head') 内第一个 button:not(:disabled)
          找不到（或不在这三类容器内）则 el = #main
9. if el: el.focus({ preventScroll: true })
          若 el 有 setSelectionRange 且 el.type === 'text'：把光标放到末尾
```

焦点签名 `focusSig(el)` 规则：

1. `el` 为空或为 `body` → 无签名（不恢复）。
2. `el.id` 存在 → `#<CSS.escape(id)>`。所以**所有需要在重绘后保持焦点的输入控件都必须有稳定 id**（源码中的 id 约定：`cq-<cc>`、`co-<cc>`、`cg-<cc>`、`cl-<cc>`、`ci-<cc>`、`hz`、`heat`、`sq`、`smulti`、`sc`、`so`、`tq`、`to`、`plq`、`plonly`、`ps-<scope>`、`wf-<scope>`、`wt-<scope>`、`sd-<cc>`、`fa-<cc>`、`bs-<bid>`、`dbs-<bid>-<lid>`、`plan-<lid>`、`note-<lid>`、`half-<lid>-<k>`、`dlid`、`projlid`、`rectab`、`uf-<id>`、`ubd`、`unb`、`unbd`、`unbf`、`unbt`、`uvc`、`vs-<id>`；按钮：分页 `pg-<scope>-prev` / `pg-<scope>-next`、详情 `pn-prev` / `pn-next`）。
3. 无 id 但有 `data-act` → 用 `FOCUS_KEYS` 中存在的 data 属性拼接属性选择器：

   `FOCUS_KEYS = ['act','v','key','page','bid','lid','scope','p','m','hk','y','id','g','view','pid','cc','t','s','q','d']`

   例：排序表头 → `[data-act="sort"][data-key="fba"][data-scope="country"]`；视图 tab → `[data-act="cview"][data-v="month"]`。
4. 无 id 且无 `data-act` → 无签名。

因为 id 优先，分页按钮（`pg-<scope>-prev/next`）即使 `data-p` 随页码变化也能找回同一个按钮；翻到首/末页后该按钮被禁用，按步骤 8 改聚焦同一分页器内第一个可用按钮（Q1）。没有 id、且签名含会随动作变化的参数的控件，重绘后找不到时焦点不恢复。`pn` 走 R-top，单独在动作内恢复焦点（3.2.4）。

### 2.3 局部派生更新（编辑计划/备注/半月计划时不整页重绘）

目的：输入框在输入过程中不能被替换（否则丢焦点、打断输入法）。实现：派生值所在节点带 `data-derived="<key>"`，`setDerived(key, html)` 把所有同键节点的 `innerHTML` 改掉。

| `data-derived` 键 | 所在位置 | 内容 | 更新时机 |
| --- | --- | --- | --- |
| `box-<lid>` | 列 `box`（国家页 overview/plan/info、发货计划页展开行“装率”列下、详情发货计划表） | `boxInner(l)`：箱数 `fmt1(qty / packRate)`，非 US 在 span 内追加小字“示例”；无数量时 `V(null)`。缺装率时整格为“缺装率”警告标签、没有该 span | `INP.plan` → `refreshPlanDerived(lid)` |
| `st-<lid>` | 状态列 `st`（`statusCell` 外包 span） | `statusInner(l)`：按优先级 同事已改 > 未保存 > 待核对 > 未分配 取第一个，多于 1 个时追加“+N” | 同上（Q6） |
| `pst-<lid>` | 计划状态标签（`planStatusTag` 外包 span；详情发货计划表、发货计划页展开行“计划合计”列下） | `planStatusInner(lid)`：草稿/已确认（示例状态）/部分执行（示例）+“未保存”+“同事已改” | 同上（Q6） |
| `hx-<lid>` | 列 `hx`（补货后可售天数）、详情发货计划表 | `fmt1((seaEnd + qty) / (avg4/7))`；只有 US 计算，其它国家为“待接入”时**不更新** | 同上（`d.v !== 'PENDING' && !d.why` 时才写） |
| `ptot-<pid>` | 发货计划页 SKU 行“计划合计” | `fmt(该 SKU 各国计划之和)` | 同上 |
| `ptotal-<pid>` | 详情“各国计划合计（含未保存）” | 同上 | 同上 |
| `pcc-<pid>-<cc>` | 发货计划页 SKU 行各国列 | `V(该国计划之和)` | 同上（只更新被编辑 Listing 所在国家） |
| `pchk-<pid>` | 发货计划页“核对”列 | 超出现货：`warn` 标签“超出现货 N”；否则 `ok` 标签“现货可覆盖” | 同上 |
| `pcheck-<pid>` | 详情“对同一份国内现货核对”说明 | `计划超出现货 N（演示核对，非原 HW 公式）` / `现货可覆盖计划合计（演示核对）` | 同上 |
| `pgrand` | 发货计划页“全部计划量合计（含未保存）” | `fmt(全部 Listing 计划之和)` | 同上 |
| `hsum-<lid>` | 国家页未来视图 / 详情未来计划“20期合计” | `fmt(sum(S.half[lid]))` | `INP.half` |
| `dlee-<pid>-<k>` | 详情“未来计划/目标”中 DL:EE 20 期国家半月计划汇总表每格（k = 0–19；k < 6 为源表空期，显示“空”） | `V(该商品所有有半月计划的 Listing 第 k 期之和, {nullText:'未设置'})` | `INP.half`，仅当 k ≥ 6（Q7） |

### 2.4 `afterRender()` 钩子（每次 `render` 结束后同步执行）

```text
afterRender():
  1. 对每个 table.t：若 thead 有 >1 行，把第一行高度写入 CSS 变量 --th1（二级表头吸顶偏移）
  2. applyPins()           // rAF 合并：按表头实际宽度计算固定列 left
  3. drawCharts()          // 立即：按容器宽度绘制所有已登记图表
  4. markScrollRegions()   // 可滚动且内部无可聚焦元素的表格容器 → tabindex=0 + role=region + aria-label
  5. if S.page === 'detail': setupAnchors()   // 详情锚点导航高亮跟随滚动
```

| 钩子 | 规则 |
| --- | --- |
| `applyPins()` | 已有待执行帧则直接返回；否则在下一帧：对每个 `table.t[data-pins=n]`（n = 固定列数，n>0），按 `thead` 第一行前 n 个单元格的 `getBoundingClientRect().width` 累加得到 `lefts`，把每一行前 n 个单元格的 `style.left` 设为对应值；遇到 `colSpan > 1` 的单元格即停止该行。固定列 CSS 类：`pin pin-<i>`，最后一个加 `pin-last`。另有静态冻结列 `fz1`/`fz2`（CSS `--fz1w` 宽度，不需要测量）。也在 `density` 切换、窗口 `resize`、`info` 切换（经 `afterRender`）时调用。 |
| `drawCharts()` | 遍历 `CHARTS`：DOM 中找不到 id 的删除登记；`type==='proj'` → `drawProj`，否则 `drawYoy`。宽度取 `max(280, el.clientWidth)`；逐年对比图 `<520px` 为窄版（高 200，隔月刻度，无端点标注），推演图 `<560px` 为窄版（高 210）。 |
| `scheduleCharts()` | rAF 合并后调用 `drawCharts()`；只在窗口 `resize` 时使用。 |
| `drawChartsThemed()` | 重新计算每个逐年图系列颜色（当年 = CSS 变量 `--link`，往年按年份倒序取灰阶 `YOY_GRAYS.light/dark`），再 `drawCharts()`。触发：`ACT.theme`、`matchMedia('(prefers-color-scheme: dark)')` 的 `change` 事件。 |
| `redrawProj(lid)` | 只重画对应 Listing 的推演图；由 `refreshPlanDerived` 调用。 |
| `markScrollRegions()` | 对每个 `.tbl-wrap`：`scrolls = scrollWidth > clientWidth+1 \|\| scrollHeight > clientHeight+1`；`hasFocusable = 内部有 button/input/select/a[href]/[tabindex]`。可滚动且无可聚焦元素 → `tabIndex=0`、`role=region`、`aria-label = 最近 .panel/.sec/.modal 中第一个 h1/h2/h3 的文字 + '（可滚动）'`，同名时追加序号“ 2”“ 3”；否则若之前标过 `role=region` 则移除这三个属性。 |
| `setupAnchors()` | 给 `#main` 绑 `onscroll`：取最后一个 `getBoundingClientRect().top < 220` 的分区（默认第一个），给对应 `.anchors button` 加 class `on`；绑定后立即执行一次。 |

### 2.5 其它局部渲染函数

| 函数 | 何时调用 | 行为 |
| --- | --- | --- |
| `renderSavebar()` | 每次 render；`INP.note`、`INP.half`、`refreshPlanDerived` | `dirtyCount()` 为 0 时清空；否则渲染未保存条（第 5 节） |

### 2.6 React 等价实现建议

| 原型机制 | React 等价 |
| --- | --- |
| `S` + innerHTML 整页重绘 | 状态放进 store（如 Zustand / Redux Toolkit / `useReducer`+Context），组件按状态渲染；不要用 `key` 强制重建页面 |
| `render({top:true})` | 路由切换后在 `useLayoutEffect` 中 `mainRef.current.scrollTop = 0` 并 `mainRef.current.focus({preventScroll:true})` |
| `rerenderKeep()` 的滚动与焦点保持 | React 默认按 key 复用 DOM，滚动与焦点天然保留。前提：表格容器、输入控件、按钮在同一页面内**不被卸载**（不要用条件渲染整体替换 `<table>` 容器；列表行 key 用业务 id） |
| `captureTables/restoreTables` | 同上天然保留；跨页面返回时用路由状态里的快照恢复（第 4 节） |
| `focusSig` | 一般不需要；若某动作会卸载当前焦点元素（例如排序后表头重建、tab 切换），用 `id`/`data-*` 在 `useLayoutEffect` 中按同样规则找回 |
| `data-derived` 局部更新 | 派生值用选择器/`useMemo` 计算；保证输入框受控且不重建。原型“输入时状态列/排序不变”的行为可以不复刻，但**输入框绝不能在输入中重建** |
| `afterRender` | `useLayoutEffect`：固定列测量（或改用 `ResizeObserver` 监听表头单元格宽度）、`markScrollRegions`（`ResizeObserver` 判断是否溢出）、锚点高亮（`IntersectionObserver` 或 scroll 监听，阈值 220px） |
| `CHARTS` 登记表 + `drawCharts` | 每个图表组件用 `ResizeObserver` 取宽度，主题从 context 取；主题或宽度变化时重画 |
| `applyPins` 的 rAF 合并 | 测量放在 `requestAnimationFrame` 中并合并同帧多次调用 |

## 3. 动作字典

### 3.1 事件分发机制（`boot()`）

| 事件 | 监听位置 | 规则 |
| --- | --- | --- |
| `click` | `document` | `t = e.target.closest('[data-act]')`。没有 `t`：若点击不在 `.gsearch` 内则 `hidePop()`，结束。有 `t`：`t.disabled` 为真则忽略；否则调用 `ACT[t.dataset.act](t, e)`（未知动作忽略）。 |
| `input` | `document` | `e.isComposing` 为真时**直接忽略**（输入法拼写中）。否则 `onText(e.target)`。 |
| `compositionend` | `document` | `onText(e.target)`（拼写结束补一次处理）。 |
| `change` | `document` | `k = t.dataset.in`；`INP[k]` 存在且 `k` 不在 `LIVE`、不在 `DEBOUNCE` 时调用 `INP[k](t)`。即：下拉框、复选框、日期框等走 `change`。 |
| `keydown` | `document` | 第 6 节。 |
| `beforeunload` | `window` | `dirtyCount() > 0` 时 `preventDefault()` + `returnValue = ''`（浏览器原生离开确认）。 |
| `resize` | `window` | `applyPins()`；`scheduleCharts()`；若宽度 > 1100 且 `S.expanded`，置 `false` 并 `renderToolbarState()`。 |
| `change`（`prefers-color-scheme`） | `matchMedia` | `drawChartsThemed()`。 |

`onText(t)`：

```text
if t.id === 'gq': showPop(); return
k = t.dataset.in; 若无 INP[k] 则返回
if k ∈ LIVE:      INP[k](t)                         // 每次输入立即处理
elif k ∈ DEBOUNCE: clearTimeout(deb[k]); deb[k] = setTimeout(() => INP[k](t), 260)
（其它键在 input 事件中不处理，等 change）
```

- `LIVE = {'plan', 'note', 'half', 'smulti', 'ccq'}`：这些处理函数都**不整页重绘**（局部更新或只写状态）。
- `DEBOUNCE = {'cq', 'sq', 'tq', 'plq'}`：文本筛选，停止输入 260ms 后执行一次（会 RK 重绘，焦点按 id 恢复、光标置末尾）。每个键各自一个计时器，在一个框输入后立刻切到另一个框输入，不会取消前一个框的处理。

## 4. 导航与返回

### 4.1 页面切换 `go(page, extra = {})`

```text
if S.page === 'detail' && page !== 'detail': S.detail = null
S.page = page; S.expanded = false; Object.assign(S, extra)
render({ top: true })
#main.focus({ preventScroll: true })
```

- 页面切换**不清空**各页自己的状态（筛选、页码、排序、tab 都保留在 `S` 中），所以回到某页时看到的是离开时的状态。
- 切换不会关闭弹层（`go` 本身不调用 `closeModal`）；会关闭弹层的是 `sku`、`goto` 动作和 `resolveConflicts`/`ccapply`。
- 不修改 `S.nav`（上一次进入详情时的来源快照保留，直到下一次从非详情页打开 SKU 时覆盖）。

### 4.2 打开 SKU 详情 `openSku(pid, o = {})`

`o`：`{ country?, lid?, list? }`。

```text
1. 若当前不在详情页：
     S.nav = [{ page: S.page,
                label: contextLabel(),
                scroll: #main.scrollTop,
                tables: captureTables(),     // 所有 .tbl-wrap[id] 的横向/纵向滚动
                list: o.list || null }]
2. from = (S.page === 'detail') ? S.detail.from : S.nav[0]
3. cc = o.country || (S.page === 'country' ? S.country : null)
4. country = (cc 且该商品在 cc 有 Listing) ? cc : 'ALL'
5. lid = o.lid || (country !== 'ALL' ? 该国第一条 Listing : null)
6. S.detail = { pid, country, lid, from,
                list: o.list || from?.list || 全部商品 pid,
                wyear: '2026', wfrom: null, wto: null }
7. S.page = 'detail'; render({ top: true }); #main.focus({ preventScroll: true })
```

来源标签 `contextLabel()`（按当前页面生成，用于“返回”按钮 `title`、工具栏副标题、返回 toast）：

| 页面 | 标签 |
| --- | --- |
| `country` | `{国家名} {cc} · {视图名}`，第 2 页起追加 `（第N页）` |
| `people` | `运营人员视图 · {人名 \| 未分配}`，第 2 页起追加 `（第N页）` |
| `search` | `搜索结果“{q}”`（q 为空时无引号部分），第 2 页起追加 `（第N页）` |
| `total` / `versions` / `stock` / `plan` / `update` / `coverage` | `总销量` / `版本记录` / `库存汇总` / `发货计划` / `数据更新与异常` / `原表覆盖与验收` |
| 其它（`notes`） | `上一页` |

视图名：`overview 综合总览、month 月历史、week 周历史、future 未来计划/目标、plan 发货计划、batch 批次与在途、stock 库存明细、info 商品资料`。

**筛选、排序、页码如何“记住”**：它们本来就在 `S`（`cui`、`S.people`、`S.search`、`S.tp` 等）里，进入详情不修改它们，返回时页面按原状态重新渲染即可还原。`NavEntry` 只额外保存了**页面滚动**与**各表格容器滚动**（含横向）。

## 5. 编辑 - 保存 - 冲突流程

### 5.1 可编辑字段与脏判断

| 字段 | 存储 | 脏判断 | 计数 |
| --- | --- | --- | --- |
| 计划量 `qty` | `S.plans[lid].qty` | `isDirtyPlan(lid)`：`qty` 或 `note` 与 `plansSaved` 不同（严格 `!==`） | 每个脏计划记 1 项（量和备注同时改也只算 1） |
| 备注 `note` | `S.plans[lid].note` | 同上 | 同上 |
| 半月销售计划 | `S.half[lid][k]` | `isDirtyHalf(lid,k)`：与 `halfSaved[lid][k]` 不同 | 每个脏期间记 1 项 |

`dirtyCount()` = 脏计划数 + 脏半月期间数。

“改回原值”即不再算脏（比较的是值，不是“是否动过”）。

### 5.2 未保存计数条（`#savebar`）

- `dirtyCount() === 0` 时为空。
- 否则渲染：`<div class="savebar" role="region" aria-label="未保存修改">`，内容依次为：圆点、`<b>N</b> 项未保存的演示修改`、`保存只写入本页内存，不会同步给同事`、按钮“放弃修改”（`data-act=discard`）、主按钮“保存到本次演示”（`data-act=save`）。
- 刷新时机：每次 render；`INP.note`、`INP.half`；`refreshPlanDerived`（`INP.plan`）。
- 不受身份控制：只读身份下若有未保存修改，条仍显示，放弃可用，保存会被拒绝。

### 5.3 保存 `save()`

```text
if !canEdit(): warn toast '当前为只读演示身份，不能保存。'; return
conflicts = 脏计划中 S.remote[lid] 存在 且 remote.version > plans[lid].version 的 lid
if conflicts 非空: conflictModal(conflicts); return
commitAll()
```

`commitAll(adopted = 0)`（`adopted` = 冲突处理中“采用同事的值”的条数，由 `resolveConflicts` 传入）：

1. `who = ROLES[S.role].name`（`运营甲` / `查看者`），`n = 0`。
1a. `synced = pullRemote(lid => !isDirtyPlan(lid))`：本地**没有修改**、但存在同事新版本的记录，直接同步同事版本（不算冲突，见 5.4a）。
2. 对每个脏计划：`version += 1`、`editedBy = who`、`updatedAt = nowStr()`；`S.log.unshift({ pid, lid, at: updatedAt, who, what })`，`what` = `` `${cc} ${msku} 计划 ${旧qty ?? '空'} → ${新qty ?? '空'}` `` + （备注变化时）`` `；备注“${新备注}”` `` + `` `（v${新版本}）` ``；`plansSaved[lid] = clone(plans[lid])`；`n += 1`。
3. 对每个有脏期间的半月计划：`S.log.unshift({ pid, lid, at: nowStr(), who, what: `${cc} ${msku} 半月销售计划修改 ${期数} 期（${期间标签以、连接}）` })`；`halfSaved[lid] = half[lid].slice()`；`n += 期数`。半月计划没有版本号，也不参与冲突。
4. RK。
5. toast：`已保存 ${n} 项到本次演示${附加}。<br><span class="muted">只写入当前页面内存，未同步给任何同事；刷新后重置。</span>`；`附加` 为空，或 `；` + 以 `，` 连接的 `采用同事的值 ${adopted} 条`、`同步同事的新版本 ${synced} 条`（各自为 0 时省略）（Q4、Q5）。

修改记录 `S.log` 显示在 SKU 详情“资料/来源”分区（按 `pid` 过滤）。

### 5.4 放弃

`discard`：`S.plans = clone(S.plansSaved)`；所有 `S.half[k] = S.halfSaved[k].slice()`；`n = pullRemote(() => true)`（同步**全部**同事新版本并清空 `S.remote`）；RK；toast `已放弃未保存的演示修改，恢复为上次保存的值。`，`n > 0` 时为 `已放弃未保存的演示修改，恢复为上次保存的值，并同步了同事的新版本 ${n} 条。`（Q5）。

### 5.4a 同步同事新版本 `pullRemote(filter)`

模拟“从服务器拉取最新版本”，返回处理条数：

```text
for lid in keys(S.remote) where filter(lid):
  r = S.remote[lid]
  S.plans[lid] = { ...clone(S.plansSaved[lid]), qty: r.qty, version: r.version, editedBy: r.by, updatedAt: r.at }
  S.plansSaved[lid] = clone(S.plans[lid])        // 该记录本人的未保存修改（含备注）一并丢弃
  S.log.unshift({ pid, lid, at: nowStr(), who: 当前身份名, what: `同步同事 v${r.version} 的值 ${r.qty}` })
  delete S.remote[lid]
```

调用方：`commitAll`（filter = 本地未修改）、`discard`（filter = 全部）。

### 5.5 模拟同事修改 `simRemote()`

1. 目标 `lid`：第一个脏计划；没有则取第一个“US 且有计划”的 Listing。
2. `S.remote[lid] = { version: plansSaved[lid].version + 1, qty: (plansSaved.qty 为数字 ? 它 : 0) + 24, by: '运营乙（模拟）', at: nowStr() }`。
3. `S.plan.open[该商品 pid] = true`（发货计划页自动展开该 SKU）。
4. RK。
5. warn toast：`模拟：运营乙已把 {cc} {SKU} 的计划保存为 {qty}（v{version}）。<br><span class="muted">修改并保存同一记录时会提示冲突。</span>`。

存在 `remote` 时的界面信号：状态列“同事已改”（`bad`，优先级最高）；计划状态标签“同事已改”；发货计划页展开行最后的合并单元格（修改人与时间之后）`同事 v{version}：{qty}`；详情“资料/来源”提示框；发货计划页“有冲突”筛选命中。

### 5.6 冲突对话框 `conflictModal(lids)`

- 标题：`版本冲突：同事已先更新 N 条计划` + 标签“模拟冲突” + 关闭按钮。
- 说明：`你的修改基于旧版本。为避免后写静默覆盖前写，请逐条选择处理方式。未处理前，你的修改保持“未保存”。`
- 每条：`{cc} · {SKU}`、`{msku} · {planId}`；`你基于的版本 v{plans.version}：{plansSaved.qty ?? '空'}`；`你的修改 {plans.qty ?? '空'}`；`同事的新版本 v{remote.version}：{remote.qty}（{by}，{at}）`；单选组 `name="cr-<lid>"`：`theirs`“采用同事的值”（默认选中）/ `mine`“重新核对后用我的值覆盖”。
- 底部复选框 `#cr-ack`：`我已核对同事的新版本（选择“用我的值覆盖”时必须勾选）`。
- 按钮：“取消，保留未保存修改”（`close`）；主按钮“确认处理并保存”（`cresolve`，`data-lids`）。

`resolveConflicts(lids)`：

```text
ack = #cr-ack.checked
choice[lid] = 选中的单选值（缺省 'theirs'）
if 任一为 'mine' 且 !ack: warn toast '请先勾选“我已核对同事的新版本”。'; return（弹层保持）
for lid in lids:
  theirs: plans[lid] = { ...clone(plansSaved[lid]), qty: r.qty, version: r.version, editedBy: r.by, updatedAt: r.at }
          // 本人对该记录的全部修改（含备注）作废（Q4）
          plansSaved[lid] = clone(plans[lid])
          log: '冲突处理：采用同事 v{r.version} 的值 {r.qty}（放弃本人对该记录的修改）'
          adopted += 1
  mine:   plans[lid].version = r.version（qty 保持我的值，仍为脏）
          log: '冲突处理：核对 v{r.version} 后以本人值覆盖'
  delete S.remote[lid]
closeModal(); commitAll(adopted)   // 'mine' 的条目在这里 version+1 并写保存记录；toast 附带“采用同事的值 N 条”
```

冲突日志的 `who` 为当前身份名，`at` 为 `nowStr()`。

### 5.7 只读身份（`role = 'viewer'`）

| 控件 | 只读时 |
| --- | --- |
| 计划量、半月计划（`editNum`） | `disabled`，`title = '只读（演示权限）'` |

## 6. 键盘与无障碍

### 6.1 全局键盘（`document` 的 `keydown`，按顺序判断）

| 顺序 | 条件 | 行为 |
| --- | --- | --- |
| 0 | 任意按键 | 先执行 `trapModalTab(e)`（只处理 Tab，见 6.2） |
| 1 | `/`，且焦点不在 `INPUT/TEXTAREA/SELECT` | 阻止默认；聚焦 `#gq` 并全选；结束 |
| 2 | `Escape` | 有弹层则 `closeModal()`；`hidePop()`；若 `S.expanded` 则收起抽屉并 `renderToolbarState()`；结束（三者在一次 Esc 中同时执行） |
| 3 | 焦点在 `#gq` 且 `Enter` | `ACT.popall()`（跳转搜索页，带当前输入）；结束 |
| 4 | 焦点在 `#gq` 且 `ArrowDown` | 若浮层有第一项则阻止默认并聚焦它；结束 |
| 5 | 焦点在 `.pop-item` 且 `ArrowDown`/`ArrowUp` | 阻止默认；聚焦下一个/上一个兄弟 `.pop-item`；没有则回到 `#gq`；结束 |
| 6 | `Enter` 或空格，焦点在 `th[data-act]`（可排序表头） | 阻止默认；`tg.click()`（触发排序） |
| 7 | `Enter`，焦点在 `input.ein` | 阻止默认；移到下一行同列第一个可用 `input.ein` 并全选（见 3.3） |

浮层项本身是 `<button>`，Enter/空格按原生按钮点击执行 `popsku`/`popall`。

### 6.2 弹层（`modal` / `closeModal` / `trapModalTab`）

| 行为 | 规则 |
| --- | --- |
| 结构 | `#modal-root > .modal-back[data-act=modal-bg] > .modal[role=dialog][aria-modal=true]`；同一时间只有一个弹层，新弹层直接替换旧内容 |
| 标题关联 | 若有 `.modal-h h2`：没有 id 则赋 `modal-title`；`.modal` 设 `aria-labelledby` 指向它（列配置弹层的 h2 id 为 `cc-title`） |
| 记录焦点归还对象 | 仅在 `#modal-root` 为空（当前无弹层）时记录 `modalReturn = document.activeElement`；弹层替换弹层时保留最初的归还对象 |
| 初始焦点 | `querySelector('[autofocus], .modal-h ~ * button:not([disabled]), button:not([disabled]), input')`（限定在 `#modal-root` 内）——选择器列表按文档顺序取第一个匹配，实际通常是标题栏的关闭按钮 |
| 关闭 | `closeModal()`：无弹层时直接返回；清空 `#modal-root`；若归还对象仍在文档中则 `focus({preventScroll:true})` |
| 关闭途径 | 关闭/取消/完成按钮（`close`）、点击背景（`modal-bg`，仅点在背景本身）、Esc、`sku`/`goto` 动作、`ccapply`、`resolveConflicts` 成功 |
| Tab 困于弹层 | 仅在存在 `.modal` 且按 Tab 时：可聚焦集合 = `button:not([disabled]), input:not([disabled]), select:not([disabled]), textarea, [tabindex]:not([tabindex="-1"])` 中 `offsetParent !== null`（可见）的元素。Shift+Tab 在第一个 → 跳到最后一个；Tab 在最后一个 → 跳到第一个；焦点不在弹层内 → 阻止默认并聚焦第一个 |

弹层清单：批次详情（`batchModal`，wide）、AWD 组成（`awdModal`）、版本详情（`versionModal`）、版本冲突（`conflictModal`）、列配置（`openColCfg`，`wide colcfg`）。

### 6.3 全局搜索浮层（`#gq` / `#gpop`）

- 输入（`input`，拼写中跳过；`compositionend` 补处理）即 `showPop()`：值 trim 后为空 → `hidePop()`；否则 `searchProducts(q)`，渲染前 6 个结果（`button.pop-item[role=option][data-act=popsku]`，含高亮 SKU、品名、命中字段标签、Listing 数），无结果时显示 `没有匹配“{q}”的 SKU / 品名 / ASIN / MSKU`，末尾固定一项 `查看全部 {N} 个结果（可组合国家/负责人） ↵`（`data-act=popall`）。显示时 `#gpop.hidden=false`、`#gq[aria-expanded=true]`。
- `hidePop()`：`hidden=true`、清空内容、`aria-expanded=false`。触发：点击 `.gsearch` 以外且不是 `data-act` 元素的位置、Esc、`popsku`、`popall`。
- 搜索结果排序：精确等于 SKU 100 分、精确等于其它字段 95、前缀 60、包含 40、品名原文包含 30；同分按 SKU 字母序。

### 6.4 输入法（IME）

- `input` 事件中 `e.isComposing` 为真时一律不处理；`compositionend` 时补调一次同样的处理。适用于所有 `data-in` 文本输入与 `#gq`。
- 列配置搜索框 `ccq` 只重写字段列表，不替换输入框本身。
- 计划/备注/半月输入只做局部更新，不替换输入框。
- React 复刻：受控输入的 `onChange` 中检查 `nativeEvent.isComposing`，拼写期间只更新输入框自身的显示值，不触发筛选/派生；在 `onCompositionEnd` 中提交。

### 6.5 焦点恢复与焦点移动汇总

## 7. 偏好与本地存储

### 7.1 存储封装

```js
store.get(k, d): try { v = localStorage.getItem('ivw:' + k); return v == null ? d : JSON.parse(v) } catch { return d }
store.set(k, v): try { localStorage.setItem('ivw:' + k, JSON.stringify(v)) } catch { /* 忽略 */ }
```

- 所有键前缀 `ivw:`，值为 JSON。
- 读写异常（隐私模式、存储禁用、JSON 损坏）一律回退默认值 / 静默忽略。
- 只在启动时读取一次；写入发生在对应动作中（无防抖）。
- 源码中没有使用 `sessionStorage`、IndexedDB 或 Cookie。业务数据（计划、修改记录、在途选择、运行记录）**从不**写入存储，刷新即重置。

### 7.2 键名、格式与校验

| 存储键 | 对应状态 | 格式 | 默认 | 写入时机 | 读取校验 |
| --- | --- | --- | --- | --- | --- |
| `ivw:theme` | `S.theme` | `"system"` \| `"light"` \| `"dark"` | `"system"` | `ACT.theme` | `pick()`：不在三值内回到 `"system"` |
| `ivw:density` | `S.density` | `"comfortable"` \| `"compact"` | `"comfortable"` | `ACT.density` | `pick()`：不在两值内回到 `"comfortable"` |
| `ivw:collapsed` | `S.collapsed` | `true` \| `false` | `false` | `ACT.collapse`（仅宽屏 >1100px 时） | 只有严格等于 `true` 才为真，其它值一律 `false` |
| `ivw:showInfo` | `S.showInfo` | `true` \| `false` | `false` | `ACT.info` | 只有严格等于 `true` 才为真 |
| `ivw:colcfg` | `S.colcfg` | `{ [view]: { cols: string[], pin: string[] } }`，view ∈ `overview / plan / stock / info / people` | `{}` | `ccapply`（写入整个对象） | 见下 |
| `ivw:tpls` | `S.tpls` | `[{ name: string, cols: string[], pin: string[] }]` | `[]` | `cctplsave`（写入整个数组） | 见下 |

`cleanCfg(c)`（列配置与模版共用）：

1. `c` 为空，或 `cols`/`pin` 不是数组 → 丢弃（返回 `null`）。
2. `cols` 只保留字符串且属于列目录全集 `ALL_COL_KEYS` 的键；过滤后为空 → 丢弃。
3. 不含 `sku` 时把 `sku` 插到最前；去重。
4. `pin` 只保留在 `cols` 中的键，最多 4 个（`PIN_MAX`）。

`colcfg` 读取：只遍历 5 个已知视图，各自 `cleanCfg`，无效的视图不写入（回退 `COL_DEFAULTS`）；其它键忽略。
`tpls` 读取：必须是数组；每项必须有字符串 `name`（截断到 40 字），与 `cleanCfg` 结果合并，`cols` 无效的项丢弃。

`pick(v, ok, d)` = `ok.includes(v) ? v : d`（定义在 `app-core.js`，偏好读回时只接受已知取值，坏值回到默认）。新工程须实现同样的校验。

### 7.3 偏好效果

| 偏好 | 生效方式 |
| --- | --- |
| 主题 | `<html data-theme="light\|dark">`，`system` 时移除属性跟随 `prefers-color-scheme`；图表颜色经 `drawChartsThemed()` 重算 |
| 密度 | `<body class="density-compact">`；切换后重新测量固定列 |
| 侧栏收起 | `#app.collapsed`（宽屏）；窄屏（≤1100px）点击同一按钮改为抽屉 `#app.expanded`（不持久化，窗口变宽、`go()`、Esc、遮罩点击都会收起） |

## 8. 通知（toast）规则

| 规则 | 值 |
| --- | --- |
| 容器 | `#toast[role=status][aria-live=polite]` |
| 同时最多 | 视口宽度 `< 720px` 时 1 条，否则 2 条；新增后超出则从最早的开始移除 |
| 持续时间 | 每条 3200ms 后移除（各自计时，不因新通知重置） |
| 结构 | 图标块（普通：`layers` 图标；`warn`：`warn` 图标 + 橙色渐变背景 `linear-gradient(180deg,#ffb340,#ff9500)`）+ 标题行 `进销存工作台` + `现在` + 正文 |

| 交互 | 无关闭按钮、无操作按钮、不抢焦点 |

全部文案：

| 列配置应用 | 默认 | `已应用列配置：{视图名} 显示 {N} 列` |

### 9.2 必须保持一致的行为清单

1. 筛选、排序、页码、tab、视图选择保存在全局状态，页面切换和进出详情都不丢失；每个国家各有一套 `cui`；切换国家只继承 `view` 与 `fut`。
2. 页码规则：筛选变化回到第 1 页；排序与 tab 切换不重置；渲染时页码越界收敛到最后一页；改每页条数回到第 1 页。
3. 排序三态：升序 → 降序 → 取消；换列从升序开始；空值视为 `-Infinity`（升序时排最前）。
4. 进入详情时记录来源（标签、页面滚动、各表格横纵滚动、上一/下一列表）；“返回”恢复这些并 toast；在详情内打开另一个 SKU 不覆盖来源；`pn` 只在来源列表内移动并保留国家选择（新 SKU 无该国 Listing 时变为全部国家）。
5. 打开 SKU、执行 `goto` 前先关闭弹层；页面切换后滚动置顶并把焦点交给主区域。
6. 文本筛选防抖 260ms（每个输入框各自计时）；输入法拼写中不处理，拼写结束补处理；重绘后焦点和光标位置（末尾）回到原输入框；翻页后焦点留在分页按钮（禁用时回到同一分页器内第一个可用按钮）；上一个/下一个 SKU 后焦点留在同一按钮（禁用时到主区域）；返回后焦点到主区域。
7. 计划量 / 备注 / 半月计划在输入过程中输入框不被重建；派生值（箱数、状态列、计划状态标签、补货后天数、各级合计、现货核对、推演图与说明、详情 DL:EE 汇总、20期合计）即时更新；同一 Listing 在同一页多处出现的计划量输入、同一 Listing 同一期的半月计划输入同步。
8. 计划量只接受空或非负整数（允许千分位逗号）；非法输入不写入状态，并显示校验提示（红框、`title`、`setCustomValidity`）。
9. 未保存计数 = 脏计划数（量或备注）+ 脏半月期间数；改回原值即不脏；有未保存修改时离开页面浏览器提示。
10. 保存：只读拒绝；有冲突（脏 且 远端版本 > 本地版本）先弹冲突框；本地未修改但有同事新版本的记录在保存时自动同步并写“同步同事 vN 的值 X”记录；版本 +1、记录修改人和时间、写修改记录；半月计划无版本。
11. 冲突框逐条选择，默认“采用同事的值”；“采用同事的值”时本人对该记录的全部修改（含备注）作废；选择“用我的值覆盖”必须勾选核对，否则拒绝并保持弹层；处理后统一保存，toast 附带“采用同事的值 N 条”。
12. 放弃恢复计划与半月计划到上次保存值，并同步全部同事新版本（清空“同事已改”）。
13. 只读身份禁用全部编辑控件（计划、备注、半月、在途批次选择）但不禁用筛选和浏览；身份切换 toast 注明“不是真实权限”。
14. 弹层：打开时记住焦点，关闭时归还；Tab/Shift+Tab 在弹层内循环；Esc 关闭；点击背景关闭（点对话框内部不关闭）。
15. 全局键盘：`/` 聚焦搜索（输入控件内除外）；Esc 同时关闭弹层、搜索浮层、窄屏抽屉；搜索框 Enter 进入搜索页、↓ 进入建议列表、建议列表 ↑/↓ 循环回搜索框；可排序表头 Enter/空格排序；可编辑单元格 Enter 跳到下一行同列。
16. 可滚动且无可聚焦内容的表格区域可聚焦（`tabindex=0`、`role=region`、带标题的 `aria-label`，重名加序号）。
17. 固定列根据表头实际宽度计算偏移；窗口大小、密度、显示说明变化后重算。
18. 图表随容器宽度和主题重画；键盘 ←/→ 逐月（对比图）或逐周 7 天（推演图）查看，失焦隐藏提示。
19. 偏好键名 `ivw:theme`、`ivw:density`、`ivw:collapsed`、`ivw:showInfo`、`ivw:colcfg`、`ivw:tpls` 与格式保持一致（便于老用户偏好延续），读取时按 7.2 校验，存储不可用时静默降级。
20. toast：宽屏最多 2 条、窄屏（<720px）1 条，3.2 秒消失，`aria-live=polite`，文案见第 8 节。
21. 列配置：`sku` 锁定不可移除；最多固定 4 列；固定列不可拖拽、不可上下移动；“保存并应用”才写入，取消/关闭不生效；模版同名覆盖，名称最多 40 字。
22. 在途批次选择：`null`（保留原范围）与 `[]`（明确空选，在途 = 0）语义不同；在 `null` 状态下勾/取消任一批次，先展开为“全部批次”再增减。
