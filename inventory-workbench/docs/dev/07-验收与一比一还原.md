# 07 · 验收与一比一还原

每个 PR 都要过四道验收：**视觉逐像素对比、行为检查、无障碍、性能**。前两道是“一比一还原”的硬保证。

## 1. 视觉逐像素对比（`tools/visual.cjs`）

### 1.1 原理

工具在**同一台机器、同一个 Chromium** 里，分别打开原型（参照）和新实现（候选）。两边都调用 `window.wbTest.open(状态ID)` 进入同一个界面状态，截图后逐像素比较。因为字体、抗锯齿、时区、日期都相同，差异只可能来自实现本身。

- 固定条件：时钟固定为 `2026-10-14T10:00:00+08:00`（底部“今天”）、`reducedMotion: reduce`、`locale zh-CN`、`timezone Asia/Shanghai`、每个状态都重新加载页面（不依赖前一个状态）、`localStorage` 为空。
- 变体：`desktop-light`（1440×900 浅色）、`desktop-dark`（1440×900 深色）、`mobile-light`（390×844 浅色，触屏）。
- 判定：任一颜色通道差 > 32 记为“不同像素”；每个状态 × 变体的不同像素占比 **≤ 0.5%** 才算通过；候选页面有脚本错误也算不通过。
- 自检结果：原型对比原型 111/111 为 0%；把表格行高改大 2px，综合总览即报 5.68% 不通过（说明能抓住细小偏差）。

### 1.2 用法

```bash
cd inventory-workbench
python3 tools/build.py                                     # 先构建原型
node tools/visual.cjs compare http://localhost:5173/        # 全部 37 个状态 × 3 个变体
node tools/visual.cjs compare http://localhost:5173/ --only country-us-overview,detail-plan --variants desktop-light
node tools/visual.cjs compare <URL> --max 0.3               # 收紧阈值
node tools/visual.cjs baseline                              # 重新生成 docs/dev/baseline/ 参照截图
```

报告输出到 `docs/dev/visual-report/index.html`（已加入 .gitignore），每个状态并排显示参照、候选、差异（红色为不同像素）。全部通过时退出码 0，否则 1，可直接放进 CI。

### 1.3 新实现必须提供的测试钩子

```ts
declare global { interface Window { wbTest: {
  states(): { id: string; title: string }[];
  open(id: string): Promise<true>;   // 进入状态，等图表、固定列绘制完成（原型等 3 帧），并清空通知
} } }
```

- 只在开发与测试环境注入即可（生产构建可去掉）。
- `open(id)` 在**刚加载的页面**上调用，必须得到与原型完全相同的界面，包括主区滚动位置。原型的实现见 `src/app-test.js`，下表“原型实现”列就是每个状态的精确定义。
- 状态 ID 只能新增，不能改名或删除。新增界面状态时，先在原型 `app-test.js` 里加，再在新实现里加。
