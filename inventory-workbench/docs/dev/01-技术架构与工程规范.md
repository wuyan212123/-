# 01 · 技术架构与工程规范

## 1. 原型现状

### 1.1 构建方式

`tools/build.py` 把 `src/` 下的文件按固定顺序拼接，内联成一个页面：

```
src/styles.css  →  <style>
src/shell.html  →  外壳 DOM
src/data.js → app-core.js → app-country.js → app-viz.js → app-cols.js → app-cover.js
           → app-detail.js → app-pages.js → app-main.js → app-test.js   →  <script>（同一作用域，全局函数）
输出：index.html（完整页面，可直接打开）、dist/workbench.html（Artifact 片段）
```

所有脚本共享一个全局作用域，不使用模块系统。**后加载的文件可以使用先加载文件里的函数**。运行时调用顺序不受加载顺序限制。

### 1.3 渲染与事件模型

- **页面注册**：`PAGES[name] = () => htmlString`。`render()` 调用当前页函数，把字符串写入 `#main.innerHTML`，再执行 `afterRender()`：测量固定列 `applyPins()`、绘制图表 `drawCharts()`、标记可滚动区域 `markScrollRegions()`。
- **事件委托**：所有可点击元素带 `data-act="动作名"` 和参数 `data-*`；所有输入带 `data-in="动作名"`。`document` 上一个监听器分发到 `ACT[name](el, event)` / `INP[name](el)`。
- **重绘**：大多数动作改完状态后调用 `rerenderKeep()`。它整页重绘，同时保持主区滚动、表格横向滚动和键盘焦点（用 `focusSig()` 生成控件签名，重绘后找回同一控件）。
- **局部更新**：编辑计划量等高频输入不整页重绘，只更新带 `data-derived="键"` 的元素（`refreshPlanDerived()`），并重画对应推演图 `redrawProj()`。
- **状态**：只有一个全局对象 `S`（详见 06）。每国界面状态在 `S.cui[cc]`，各表分页在 `pstate()`。

## 2. 目标架构（建议）

### 2.1 推荐技术栈

| 层 | 建议 | 理由 |
| --- | --- | --- |
| 语言 | TypeScript（strict） | 数据实体多、缺失值语义复杂，需要类型约束 |
| 框架 | React 18 + Vite | 生态成熟；组件可以输出与原型完全相同的 DOM |
| 样式 | **原样引入 `src/styles.css` 作为全局样式** | 一比一还原的根本保证。**不要**用 Tailwind、CSS Modules、CSS-in-JS 或任何 UI 组件库（Ant Design、MUI 等），它们会改变 DOM 与样式 |
| 状态 | 本地界面状态：Zustand（或 useReducer + Context）；服务器数据：TanStack Query | 对应原型 `S` 中“界面状态”与“业务数据”两类 |
| 路由 | React Router（hash 或 history 均可） | 原型无路由；正式版建议加，但不得改变界面 |
| 图表 | 手写 SVG（移植原型的绘制函数） | 原型图表的几何、颜色、标注都是手写的；换图表库无法一比一 |
| 表格 | 自研 `<Table>`，输出与 `table()` / `th()` / `pagedTable()` 相同的 DOM | 冻结列、固定列、吸顶表头、可编辑格都依赖特定类名 |
| 测试 | Playwright（端到端）+ Vitest（计算函数） | 与原型的验证工具一致 |

> 若团队已有既定技术栈，可以替换框架，但第 2.3 节“必须保持一致的实现约束”不能变。

### 2.2 目录建议

```

    app/                          ← 外壳：Sidebar、Toolbar、SourceBar、SaveBar、Toast、ModalRoot
    components/                   ← V（值显示）、Tag、Icon、Seg、Table、Pager、Panel、Metric、Callout、Empty

      detail/                     ← DetailPage + 7 个分区
      people/ search/ total/ stock/ plan/ update/ versions/ coverage/ notes/
    domain/                       ← 纯函数：transitOf、coverOf、boxesOf、daysAfterOf、汇总口径（可直接单测）
    data/
```

### 2.3 必须保持一致的实现约束

1. **样式**：`styles.css` 一个字都不改。新增样式另建文件，且不能覆盖原有选择器。
2. **DOM 与类名**：每个组件输出的元素层级、类名、`id`、`role`、`aria-*`、`data-*` 与原型一致。端到端测试与视觉对比都依赖这些属性。表格 `id` 规则也要一致，例如 `tbl-US-overview`、`tbl-US-month`、`tbl-stock-aging`、`tbl-versions`。
3. **文案**：逐字一致，包括全角标点、中点“·”、箭头“→”、破折号“—”、空格。
4. **数字格式**：千分位用 `new Intl.NumberFormat('zh-CN')`，整数先四舍五入（`fmt`）；一位小数用 `toFixed(1)`（`fmt1`）；百分比 `(n*100).toFixed(1)+'%'`。
5. **日期**：业务日期一律取数据基准日（`S.baseDate`，演示为 2026-10-11，演示更新后可变）。只有底部来源条的“今天”取浏览器日期。
6. **演示数据**：第一阶段必须使用与原型**完全相同的生成结果**（移植 `data.js`，种子、调用顺序、`?scale=N` 都不变），否则视觉对比无法通过。
7. **字体**：只用系统字体栈（见 02），不引入网络字体。
8. **图标**：内联 SVG，路径与原型 `ICONS` 一致。
9. **测试钩子**：实现 `window.wbTest`，状态 ID 与 `src/app-test.js` 一致，打开后的界面与原型相同（见 07）。

### 2.4 从原型移植的方式

建议按“函数 → 组件”逐个移植，不要凭截图重画：

| 原型 | 新工程 | 移植要点 |
| --- | --- | --- |
| 返回 HTML 字符串的函数（如 `coverCell(l)`） | 同名 React 组件 / 函数 | 模板字符串原样改成 JSX，属性名改为 React 写法（`class` → `className`、`for` → `htmlFor`、`tabindex` → `tabIndex`、`aria-*` 保持） |
| `data-act` + `ACT[name]` | 组件内事件处理 | 行为逐条对照 06 的动作字典；需要的 `data-*` 属性仍要输出（测试用） |
| `rerenderKeep()` | React 自动重绘 | 必须保持：重绘后焦点留在原控件、主区与表格滚动位置不变（React 默认如此，注意不要因 `key` 变化导致重新挂载） |
| `data-derived` 局部更新 | 派生状态 / selector | 输入时不能导致整表重新挂载，否则输入框失焦、中文输入法被打断 |
| `afterRender` 里的测量（固定列、图表宽度） | `useLayoutEffect` + `ResizeObserver` | 固定列的 `left` 偏移与原型的 `applyPins()` 算法一致 |
| `localStorage`（键前缀 `ivw:`） | 偏好 store | 键名与格式保持，读取时校验（见 06） |

### 2.5 代码规范

- 计算逻辑（汇总、在途、可撑天数、箱数等）全部放在 `domain/`，写成纯函数并配单元测试。单测的期望值直接取原型在相同输入下的输出。
- 组件只负责显示，不在组件里写业务公式。
- 缺失值统一用一个类型表示，例如 `type Val = number | 'NF' | 'NP' | 'FU' | 'EMPTY' | 'PENDING' | null`，渲染统一走 `<V>` 组件（对应原型 `V()`）。
- 所有用户可见文本集中在组件里，不要从英文翻译生成。
- 提交前运行：类型检查、单元测试、端到端测试、视觉对比、axe。

## 3. 第二阶段：接后端后的数据流

```
后端接口（05）──TanStack Query──▶ 领域数据（与 mock 同结构）──▶ domain/ 纯函数 ──▶ 组件
                                  ▲
界面状态 store（筛选、页码、排序、视图、列配置、偏好）
写操作：计划量/备注/半月计划 → PATCH（带版本号）→ 409 冲突 → 冲突对话框（原型已有界面）
```

- mock 与真实接口返回**同一套类型**，切换只改数据源。
- 视觉对比在第二阶段仍用 mock 数据运行（`?mock=1` 或测试环境开关），保证界面没有回退。
