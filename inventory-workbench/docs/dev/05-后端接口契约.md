# 05 · 后端接口契约（建议设计）

> **本文件全部为建议设计，需与后端确认。** 原型没有任何后端（`docs/02-状态说明.md`“设计占位”）；这里按原型实际读写的数据与交互反推接口。字段名与 [04-数据模型与业务规则](04-数据模型与业务规则.md)（下称“04”）一致；规则编号 `R-xx`、`P-xx` 指 04 中的条目；`#n` 指 `docs/04-待确认项.md`。
> 原型事实均注明源码位置；没有注明位置的设计细节（路径、错误码、分页参数名、事务边界、角色名等）都是建议。

## 0. 通用约定

### 0.1 基本

| 项 | 约定（建议） |
| --- | --- |
| 前缀 | `/api/v1` |
| 格式 | `application/json; charset=utf-8`；上传用 `multipart/form-data` |
| 认证 | 会话 Cookie 或 `Authorization: Bearer <token>`；全部接口需登录 |
| 时间 | 日期 `YYYY-MM-DD`；时间戳 ISO 8601 带时区（原型显示为 `YYYY-MM-DD HH:mm`，前端格式化） |
| 数据版本 | 所有读接口在 `meta` 中返回当前数据版本 `versionId` 与 `baseDate`；可选查询参数 `version=<versionId>` 读取历史版本快照（仅版本对比/快照接口必须支持，其余接口可后续扩展） |
| 语言 | 错误 `message` 为中文，可直接展示 |

### 0.2 值编码（与 04 第 2 节一致）

数值字段统一编码为：

```
Val = number | "NF" | "NP" | "FU" | "EMPTY" | "ERR" | "PENDING" | null
```

- 原因码原样下发，**后端不得把原因码折算为 0 或 null**；真实 0 就是数字 `0`。
- `null` 表示“人工字段未填 / 无记录”，前端按语境显示（未设置、未填、原表未设、无记录…，见 04 §2.1）。
- 只在“空白（domesticBlank）”这种行级标志上用布尔字段，不新增原因码。
- 汇总值（合计、小计）建议附带 `missingCount`（参与范围内非数值项的个数），便于前端提示“仅数值项之和”。

### 0.3 列表、分页、排序

查询参数：

| 参数 | 类型 | 说明 |
| --- | --- | --- |
| `page` | int ≥ 1 | 页码，默认 1；超出最后一页时后端返回最后一页并在 `page` 中回写实际页码（与原型 `if (st.page > pages) st.page = pages` 一致） |
| `size` | int | 每页条数，必须在该列表允许集合内（见下表），否则 400 |
| `sort` | string | 排序键（各列表白名单见各接口） |
| `dir` | `asc` \| `desc` | 默认 `asc`；原型点击表头循环：升序 → 降序 → 取消排序 |
| `nulls` | `first` \| `last` | 可选。默认与原型一致：null/原因码视为 −∞（升序在前、降序在后） |

响应：

```json
{
  "items": [],
  "page": 1,
  "size": 12,
  "total": 87,
  "meta": { "versionId": "V-1012", "baseDate": "2026-10-11" }
}
```

原型各列表的每页条数（app-core.js `pager` / `pagedTable`、各页 `pager` 调用）：

| 列表 | 允许 `size` | 默认 |
| --- | --- | --- |
| 国家主表（每国） | 8, 12, 25, 50 | 12 |
| 运营人员视图 | 8, 12, 25, 50 | 12 |
| 全局搜索 | 8, 12, 25 | 8 |
| 总销量 | 8, 12, 25 | 8 |
| 发货计划、库存汇总各表、按 Listing 批次明细、过程记录 | 25, 50, 100 | 25 |

### 0.4 错误格式

```json
{
  "error": {
    "code": "VERSION_CONFLICT",
    "message": "同事已先更新 1 条计划，请逐条选择处理方式",
    "details": {}
  }
}
```

| HTTP | `code` | 场景 |
| --- | --- | --- |
| 400 | `VALIDATION_FAILED` | 参数非法：`size` 不在允许集合、`sort` 不在白名单、计划量不是非负整数（原型 `parseQty`：去千分位后须匹配 `^\d+$`）、半月期键不存在 |
| 401 | `UNAUTHENTICATED` | 未登录 |
| 403 | `FORBIDDEN` | 角色无权（例如查看者保存计划；见 §6） |
| 404 | `NOT_FOUND` | pid/lid/bid/planId/versionId/importId 不存在 |
| 409 | `VERSION_CONFLICT` | 计划/半月计划/在途选择/视图配置的 `baseVersion` 落后，`details` 返回对方值 |
| 409 | `DATA_VERSION_CHANGED` | 导入预检后当前数据版本已变化（R-74） |
| 409 | `IMPORT_IN_PROGRESS` | 已有其他导入在应用中 |
| 422 | `NOT_APPLICABLE` | 对不适用的国家/字段写入（如给 SA 写计划量、给 AE 写半月计划） |
| 422 | `PRECHECK_REQUIRED` | 未预检或预检已过期就应用 |
| 422 | `ACK_REQUIRED` | 冲突后用自己的值覆盖但未声明已核对（R-44） |
| 500 | `INTERNAL` | 服务端错误 |

### 0.5 国家与适用性

所有带 `country` 的接口：`country ∈ {US,CA,AU,UK,EU,AE,SA}`；人员视图、搜索等支持 `ALL`。不适用的视图/字段（`CMAP` 的 `weeks/half/fiscal/variant/domestic/awd/stocking` 为 false）读接口返回 `"NF"` 或省略该块并在 `applicable` 中标 false；写接口返回 422 `NOT_APPLICABLE`。

## 2. 读取接口

### 2.1 国家主表 · `GET /api/v1/countries/{cc}/listings`

对应原型国家主表 8 个视图（app-country.js `PAGES.country` / `countryView`）的 SKU 行。

查询参数：

| 参数 | 说明 | 原型 |
| --- | --- | --- |
| `q` | 关键词，归一化包含匹配 SKU/品名/ASIN/MSKU（R-80 的 `norm`） | `cui.q` |
| `owner` | `ALL`（默认）\| 人名 \| `__none`（未分配） | `cui.owner` |
| `grade` | `ALL` \| `A` \| `B` \| `C` \| `新品` | `cui.grade` |
| `label` | `ALL` \| `常规` \| `季节性` \| `清货` \| `新品` | `cui.label` |
| `issueOnly` | bool：仅看待核对（有 Issue 或变体 kind ∈ zeroden/outgroup/referr） | `cui.issue` |
| `view` | `overview` \| `month` \| `week` \| `future` \| `plan` \| `batch` \| `stock` \| `info`，决定返回哪些块（见下） | `cui.view` |
| `years` | 逗号分隔，月历史年份；省略 = 全部 | `S.years` |
| `weekFrom` / `weekTo` / `weekYear` | 周范围（`2026-W30`）/ 源周区年份（`ALL` 或 `2024`…） | `wfrom/wto/wyear` |
| `fields` | 可选，逗号分隔列键（附录 A），只返回这些列需要的字段 | 列配置 |
| `sort` / `dir` / `page` / `size` | 见 §0.3 | — |

**排序键白名单**（原型 `LISTING_SORT`，app-country.js `LISTING_SORT`；可排序列在列目录中带 `sort:true`，`app-cols.js`）：

| `sort` | 取值 | 原型 |
| --- | --- | --- |
| `cover` | 可撑天数“最急”键：不适用/无销量 = 1e9；断档 = `gapFrom − 1000`；其余 = `total`（R-54，演示估算） | ✓ |
| `sku` | SKU 字符串 | ✓ |
| `fba` | FBA 可售 | ✓ |
| `transit` | 当前在途（按该国当前在途选择） | ✓ |
| `avg4` | 近4周均销（非数值 → null） | ✓ |
| `plan` | 本次计划量（服务端按已保存值，见下注） | ✓ |
| `m9` | 2026-09 月实际（非数值 → null）；建议泛化为 `month:YYYY-MM` | ✓ |
| `owner` | 负责人（null → 空串） | ✓ |
| `name`、`asin`、`msku`、`grade`、`dom`、`transfer`、`a1`、`a2`、`a3`、`v180`、`daysNow`、`daysTotal`、`awd`、`overseas`、`wLatest`、`m10`、`y2025`、`y2026`、`half`、`sea`、`hx`、`weight` | 对应附录 A 列 | **建议新增**（原型这些列不可排序） |

## 3. 写入接口

> 所有写入：需要 `editor` 或以上角色（§6）；请求体带 `baseVersion`（乐观锁）；成功返回新版本与服务端最终值；全部写入记审计日志（谁、何时、对象、旧值、新值、版本号）。原型对应 app-main.js `commitAll` / `pullRemote` / `save` / `conflictModal` / `resolveConflicts` / `simRemote`（保存/冲突）与 app-main.js `ACT.bselall` / `ACT.bselnone` / `ACT.bselorig` / `INP.bsel`（在途选择）。

### 3.1 计划量 / 备注

#### `PUT /api/v1/plans/{planId}`

单条保存。请求：

```json
{ "qty": 168, "note": "跟随0915批次", "baseVersion": 3 }
```

- `qty`：非负整数或 `null`（清空 = 未填）；其他值 → 400 `VALIDATION_FAILED`（R-44 / `parseQty`）。
- `note`：字符串（建议上限 500 字）。
- 该 Listing 所在国家无计划区（SA）→ 422 `NOT_APPLICABLE`。

响应 200：

```json
{ "plan": { "planId": "PL-US-001", "lid": "L-US-001", "qty": 168, "note": "跟随0915批次", "status": "draft", "version": 4, "editedBy": "运营甲", "updatedAt": "2026-10-15T09:41:00+08:00" },

```

响应 409 `VERSION_CONFLICT`（对方已先保存；**不写入**）：

```json

    "code": "VERSION_CONFLICT",
    "message": "同事已先更新该计划，请选择采用同事的值或核对后覆盖",
    "details": {
      "conflicts": [
        { "planId": "PL-US-001", "lid": "L-US-001",
          "base": { "version": 3, "qty": 144, "note": "" },
          "yours": { "qty": 168, "note": "跟随0915批次" },
          "theirs": { "version": 4, "qty": 168, "note": "", "editedBy": "运营乙", "updatedAt": "2026-10-15T09:30:00+08:00" } }
      ]
    }
  }

```

冲突处理（与原型 app-main.js `conflictModal` / `resolveConflicts` 对应，规则见 04 R-44）：

- **采用同事的值**（原型默认选项）：前端**丢弃本人对该记录的全部修改，包括备注**，把本地值与“已保存值”都替换为 `theirs`（整条记录：`qty`、`note`、`version`、`editedBy`、`updatedAt`），不再为该记录发请求；该记录计入“采用同事的值 N 条”。原型中远端版本只带计划量，因此备注回到上次已保存值；正式版 `theirs` 含备注，直接整条采用即可，二者都意味着“本人修改作废”。
- **重新核对后用我的值覆盖**：前端必须先让用户勾选“我已核对同事的新版本”，然后重新提交本人**完整的** `qty` 与 `note`，`baseVersion = theirs.version`，并带 `"overrideAck": true`；成功后服务端版本为 `theirs.version + 1`。缺少 `overrideAck` 而 `baseVersion` 来自冲突时，后端可返回 422 `ACK_REQUIRED`（建议：后端只做版本校验，把 `overrideAck` 写入审计作为“已核对”的证据）。
- **取消**：不发请求，本人修改保持“未保存”。

#### `POST /api/v1/plans:batch-save`

“保存”按钮一次提交全部未保存修改（原型 `save` → `commitAll` 一次保存所有脏 Plan 与半月计划）。**全有或全无**：任一条冲突 → 409，返回全部冲突，**整批不写入**（与原型一致：有冲突时先弹窗，处理前其他不冲突的修改和半月计划也都不写入，全部保持未保存）。处理完冲突后，前端用“去掉已采用同事值的记录、覆盖项改用新 `baseVersion`”的新请求再次提交。

请求：

```json
{
  "plans": [ { "planId": "PL-US-001", "qty": 168, "note": "", "baseVersion": 3, "overrideAck": false } ],
  "halfPlans": [ { "lid": "L-US-001", "changes": [ { "period": "2026-11上", "value": 300 }, { "period": "2026-12下", "value": null } ], "baseVersion": 2 } ],
  "knownVersions": { "PL-US-002": 1, "PL-CA-004": 2 }
}
```

- `knownVersions`（建议，可选）：前端当前已加载、但**本人未修改**的计划记录及其版本。服务端在成功响应的 `synced` 中返回其中已有更新版本的记录，前端直接并入（对应原型 `pullRemote`：保存时自动同步“本地未改但有同事新版本”的记录，不算冲突）。也可以不传，改为保存成功后重新拉取当前列表，效果相同。

响应 200：

```json
{
  "plans": [ { "planId": "PL-US-001", "qty": 168, "note": "", "version": 5, "editedBy": "运营甲", "updatedAt": "…" } ],
  "halfPlans": [ { "lid": "L-US-001", "values": [240, 255, null], "version": 3 } ],
  "savedCount": 3,
  "synced": [ { "planId": "PL-US-002", "qty": 120, "note": "", "version": 2, "editedBy": "运营乙", "updatedAt": "…" } ]
}
```

`savedCount` = 本人提交的计划条数 + 半月期数（原型提示“已保存 N 项”）；`synced.length` 对应原型提示里的“同步同事的新版本 N 条”；“采用同事的值 N 条”由前端在冲突处理时自行计数（这些记录不在请求中）。
响应 409：`details.conflicts[]` 同 `PUT /plans/{planId}`；半月计划冲突项为 `{ "lid", "type": "half", "base": {...}, "yours": {...}, "theirs": { "version", "values", "editedBy", "updatedAt" } }`（原型半月计划没有冲突检测，此为建议）。

#### 放弃修改（无接口）

原型 `ACT.discard`：全部恢复为上次保存值，并同步**全部**同事新版本。正式版：前端丢弃本地修改后重新拉取当前页面数据（或带 `knownVersions` 调用 `GET /api/v1/plans/versions?ids=…`，建议），使所有记录都是最新已保存版本；不需要写接口。

### 3.2 半月销售计划

#### `PATCH /api/v1/listings/{lid}/half-plan`

```json
{ "changes": [ { "period": "2026-11上", "value": 300 } ], "baseVersion": 2 }
```

- `period` 必须是 20 期 `HALF[].key` 之一；`value` 非负整数或 `null`（未设置，≠ 0）。
- 国家 `half=false`（AE/SA）→ 422 `NOT_APPLICABLE`。

- 半月计划只改销售计划，不影响实际销量、发货计划或库存（R-43）；保存后 DL:EE（`/total/blocks?blk=forecast`）随之变化。

响应 200：`{ "lid": "L-US-001", "values": [Val×20], "sum": 4870, "version": 3, "editedBy": "运营甲", "updatedAt": "…" }`；409 同 §3.1。

## 4. 导入流程（上传 → 指纹 → 预检 → 预览 → 应用）

> 对应原型“数据更新与异常”五步（app-pages.js `newUpd` / `updPlan` / `updPreview` / `PAGES.update`）与 04 R-70～R-78。原型全部为占位；以下为建议设计。

### 4.1 状态机（建议）

```
draft ──上传/设置──▶ draft ──precheck──▶ prechecked ──apply──▶ applied（生成 pending 版本）──confirm──▶ 当前版本(cur)
  │                       ▲   修改文件/设置后回到 draft            │
  └────────── cancel ─────┴────────────────────────────────────── ▶ cancelled
apply 时当前数据版本 ≠ 预检基于的版本 ──▶ 409 DATA_VERSION_CHANGED，状态回到 draft（须重新预检）
```

同一时间只允许一个导入处于“应用中”（409 `IMPORT_IN_PROGRESS`）。

### 4.2 接口

#### `POST /api/v1/imports`

创建导入会话。请求：`{ "baseDate": "2026-10-13" }`（可后续修改）。响应 201：`{ "importId": "IMP-20261015-001", "status": "draft", "basedOnVersion": "V-1012" }`。

#### `POST /api/v1/imports/{importId}/files`（multipart）

字段：`file`、`purpose ∈ main_prev（上一版主表，必需）| update_log（配套更新记录，必需）| fba | domestic | sales_daily | shipment_snapshot | awd`。

响应 201：

```json
{ "fileId": "F-7", "name": "货件详情_1013.xlsx", "purpose": "shipment_snapshot", "size": 482113,
  "fingerprint": "sha256:5a80…c1e", "included": true, "required": false,
  "duplicateOf": null }
```

- 指纹建议对文件内容做 SHA-256；**与本会话已有文件指纹相同 → `duplicateOf` 指向那个文件，预检时该文件“跳过”，不相加**（R-70）。
- 建议同时校验：扩展名、工作表/表头是否符合用途；不符时返回 422 并说明。

`{ "included": false, "purpose": "fba" }`。必需文件不可取消纳入（原型复选框禁用）→ 422。

#### `DELETE /api/v1/imports/{importId}/files/{fileId}`

#### `POST /api/v1/imports/{importId}/apply`

请求：`{ "basedOnVersion": "V-1012", "confirm": true }`。

- 未预检或预检后文件/设置有变动 → 422 `PRECHECK_REQUIRED`。
- 当前数据版本 ≠ `basedOnVersion`（他人已更新）→ 409 `DATA_VERSION_CHANGED`，**本次没有任何数据被写入**，状态回到 `draft`（R-74）。
- **事务性**（R-72）：一次应用在单个数据库事务内完成：可更新模块的数据写入、批次行与原发货历史写入、在途重算、来源状态（freshness）更新、过程记录 14 张表、Issue、运行记录、新版本快照；任一步失败整体回滚。
- 人工数据（计划量、备注、半月计划、财年目标、产品等级）不被覆盖。

响应 200：

```json
{
  "runId": "RUN-20261015-001", "versionId": "V-1013", "versionStatus": "pending",
  "applied": { "fba": 98, "sales": 180, "shipment": 34 },
  "kept": ["awd"], "blocked": [], "skipped": ["duplicate"],
  "freshness": [ { "key": "fba", "date": "2026-10-13", "state": "updated" }, { "key": "awd", "date": "2026-10-04", "state": "stale" } ],
  "baseDate": "2026-10-13"
}
```

- 销量模块 `ok` 时数据基准日更新为新基准日；`block` 时销量 `state=blocked`，保留旧值与旧基准日（R-75）。
- FBA 未更新时 `staleFba=true`，依赖它的可售天数需标“依赖旧库存”。

#### `POST /api/v1/versions/{versionId}/confirm`（确认人）

把 `pending` 版本设为当前版本（原有 `cur` 变 `hist`）。**建议**：在确认前，读接口默认仍读旧的 `cur` 版本，或提供开关让编辑者预览 `pending` 版本；具体由 #6、#17 确认。

#### `DELETE /api/v1/imports/{importId}`

取消草稿/已预检的导入；已应用的不可删除（需走版本作废）。

#### `GET /api/v1/imports/{importId}`

查看会话状态、文件、设置、最近一次预检结果。

## 6. 权限角色（建议，**待确认 #6**）

| 团队级列配置、团队模版 | ✗ | ✗ | ✓ |
| 创建导入、上传、预检、预览（§4） | ✗ | ✓ | ✓ |
