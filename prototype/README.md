## 页面与路由

`#cycle` 周期优化（默认首页）· `#overview` 经营总览 · `#diagnosis` 复盘分析 · `#keywords` 关键词决策 · `#reports` 复盘报告 · `#data` 数据中心 · `#projects` 项目 · `#rules` 分析规则 · `#spec` 方案说明（信息架构、模块去向、表格规范、响应式与优先级）

左下角「状态演示」可切换：无项目、空项目、范围无数据、清单筛选为空、无历史基准、覆盖不足、读取失败、导入待确认/完成/失败、报告生成中，以及“下次范围更新失败”。

## 落地到现有 React + TypeScript 应用时的对应关系

- 全局分析范围 `scope`（来源、A/B、维度筛选）与已显示范围 `shown` 分开存储：请求中/失败时界面保留 `shown` 的结果并标明，导出与报告生成禁用。
- 关键词清单视图 `list`（标签、搜索、订单、排序、分页）与列偏好 `cols / colW`（localStorage）不进入导出参数。
- 指标比率一律由汇总基础量重算（`derive()`），分母为 0 显示“—”。
- 图标为 Lucide 0.460.0 的内联 SVG，对应 `lucide-react` 同名组件；图表可用 Recharts 重做，规格见页面。
- 标注虚线「新增」的元素（变化贡献分解、活动分化标签等）属于新增展示，需单独评审。

## v3 相对 v2 的变化（参考 Linear、Stripe、Shopify Polaris、Google Ads、Vercel Geist）

- 视觉：浅色、变暗的导航栏让内容优先；Geist 字体与等宽数字；卡片阴影收至最轻。
- 总览：指标卡即标签页，点选后下方趋势图切换为该指标（单一纵轴）；页头显示本轮进度（处理风险词 n/m → 生成复盘）；待处理队列显示已处理数。
- 关键词清单：视图标签（全部 / 风险 / 机会 / 变化 / 需核查 / 已处理）、标签下拉、舒适 / 紧凑行高、勾选后切换为批量操作条。
- 人工判断：详情中“采纳 / 暂不处理”，批量也可标记；记录写入复盘报告“本轮人工判断”。原型存于浏览器 localStorage，实际应存后端。
- 键盘：⌘K / Ctrl+K 或 / 打开命令面板（搜关键词、跳页面、执行常用操作）；清单中 J/K 上下、Enter 打开详情、X 选择、Esc 关闭。
- 以上新增交互在页面上用虚线“新增”标出，详细对照见 `#spec` 方案说明页的“参考的优秀产品与借鉴点”。

## v4 相对 v3 的变化：先结论、再证据

- **本期结论**（总览左上）：一句话回答“表现怎样、为什么”，如“广告销售额日均下降 21.5%，主要来自 CVR 下降”；下方是 销售额 = 曝光 × CTR × CVR × 客单价 的四个因素及各自贡献，并列出拖累 / 贡献最大的词。全部由规则计算，标注“非 AI”。
- **变化拆解**（变化诊断页）：瀑布图，可切换销售额 / 花费 / ACOS。采用对数均值分解（LMDI），各因素贡献之和等于总变化、无残差；A/B 覆盖天数不同时量指标按日均。纵轴截取到变化区间，总额柱带断轴记号并在说明中注明起点。关键词详情中也给出该词的销售额拆解。
  - 计算：`L = (A−B)/ln(A/B)`，因素 i 的贡献 `= L × ln(xᵢ,A / xᵢ,B)`；ACOS = CPC ÷ (CVR × 客单价)，CVR、客单价取负号。实现见 `decompAB()`。
- **覆盖提示**：从整行横幅收为页头的“覆盖不足”标记，点击弹出 A/B 覆盖天数与缺日。
- **表格**：B 列可切换为“变化”（按指标含义着色，可排序）；手机端关键词改为卡片列表；总览重点词增加近 8 周花费小图。
- **细节**：切换页面时内容轻微上浮淡入（尊重“减少动态效果”设置）；深色模式下图表 A/B 区间底色减淡；1024–1440 之间顶栏自动收紧，不再换行或遮挡。

## v5：按资深运营的周期优化流程重组

新增默认首页 **周期优化**（`#cycle`），把每周一轮的关键词优化做成 6 步工作台，每步右侧写明规则与资深做法：

1. **准备与回看**：决策窗口检查（最近 N 天归因未结算、样本天数、覆盖、报表来源、目标 ACOS 与盈亏平衡 ACOS），一键改用“近 14 天、排除最近 3 天”；上期动作回看（执行前 B → 执行后 A：改善 / 持平 / 变差 / 仍有花费需核实）。
2. **诊断**：本期结论与销售额拆解；活动表现表给出“ACOS 超标 → 本周重点调价 / 达标且花费上涨 → 检查预算”等判断，可直接跳到该活动的调价。
3. **收割**：自动 / 广泛 / 词组中订单 ≥ 2 且 ACOS 达标、尚无精准投放的搜索词 → 精准投放；建议出价 = 每次点击收入 × 目标 ACOS（限制在 CPC 的 0.9–1.6 倍）；自动在来源广告组加否定精准。
4. **否定**：点击 ≥ 阈值或花费 ≥ 1.5 × 目标 CPA 且无订单 → 否定精准 / 否定 ASIN；品牌词只复核；显示每周浪费金额。
5. **调价**：在投放层（关键词 / 定向）分桶：亏损降价（目标 ÷ 实际，单次上限 30%）、无单阶梯降价、暂停、盈利提价、维持、观察；报表无当前出价，参考出价由 CPC 推算。
6. **确认导出**：动作汇总与每周节省粗估、亚马逊批量操作表预览（Entity / Operation / Campaign / Ad Group / Keyword / Match Type / Bid / State）、导出动作日志、完成本周期（写入复盘“本周优化动作”）。

新增规则参数（分析规则 → 周期优化参数）：盈亏平衡 ACOS、收割最少订单、提价幅度、无单降价、单次降价上限、排除最近未结算天数。

落地注意：上期回看在原型中由 B 期数据按同一规则推算（标注为演示记录），正式版应读取上期“完成本周期”保存的动作日志；批量表需与后台下载的批量表匹配 Campaign / Ad Group / Keyword ID 后上传。

## v6：资深运营的多维度周期复盘

“变化诊断”升级为 **复盘分析**（`#diagnosis`），在原 A/B 对比之外新增四个维度。全部沿用顶部分析范围与筛选；周趋势按 A 期结束日倒推 12 个 7 天区间（与分析窗口对齐、避免半周），有缺日的区间单元格带圆点。

| 维度 | 内容 | 关键口径 |
| --- | --- | --- |
| 活动趋势 | 活动 × 周热力表（ACOS / 花费 / 销售额 / 订单 / CVR / CPC）、周环比、趋势判断、花费占比 vs 销售占比 | ACOS 以目标为中点双色（低于目标蓝、高于目标红）；其他指标按行着色。趋势判断看最近几周 ACOS 与日均花费的连续变化（±2% 以内不算变化），“超目标”与其他规则一致按目标 × 1.1 |
| 关键词变动 | 新增 / 增长 / 下滑 / 消失 / 稳定 五类卡片，变动清单（B → A、差值、主因、近 12 周订单），头部 20 词 × 周热力表，集中度 | 增长 / 下滑以销售额 ±20% 为界且差额 ≥ $20；主因 = 该词销售额拆解（曝光 × CTR × CVR × 客单价）中贡献最大的因素；天数不同时按日均 |
| 结构与效率 | 匹配方式周结构与 ACOS、品牌 / 非品牌拆分（非品牌 ACOS）、无效花费率走势、效率分层散点、同词多活动竞价 | 无效花费率 = 近 14 天点击 ≥ 无转化阈值且无订单的搜索词花费 ÷ 总花费；散点横轴花费（平方根刻度）、纵轴 ACOS，参考线为目标 ACOS 与目标 CPA；同词多活动以“订单多、ACOS 低”的活动为保留建议 |
| 星期规律 | 星期 × 指标热力表、规律总结 | 近 8 周；可排除销售额超过均值 + 2.5σ 的异常日（如大促）；比率以均值为中点，蓝色为有利 |

另外：周期优化“诊断”步骤的活动表增加近 8 周 ACOS 迷你线与趋势判断，并给出关键词变动计数；复盘报告新增“趋势与结构”一节；命令面板可直接跳到各复盘维度。

数据边界：TACoS 需要业务报告中的店铺总销售额；版位、展示份额需要版位报表或搜索词展示份额报告；小时级分析需要 Amazon Marketing Stream 等数据。均为新增范围。

## v6.1：关键词决策页恢复“变动”维度

- 关键词决策页在视图标签下方新增常驻 **变动** 筛选：全部 / 新增 / 增长 / 下滑 / 消失 / 稳定，带计数，可与“风险 / 机会”等视图叠加。
- 变动依据可切换：销售额（默认）/ 订单 / 点击 / 花费。新增 = B 期为 0、A 期有值；消失 = B 期有值、A 期为 0；增长 / 下滑 = 变化超过 ±20% 且差额达到最小值（销售额 $20、订单 2、点击 5、花费 $10），避免 1 单之差的噪音；天数不同按日均。
- 表格新增默认列 **变动**（类型 + 变化幅度，悬停看 B → A），按此列排序 = 按变化幅度从大到小；手机卡片同样显示。
- 复盘分析的关键词变动改用同一规则（`mvOf()`），两处计数一致；变动清单可一键“在关键词决策中处理”。
- 原“变化”视图更名为“提升”（CTR / CVR 提升、新增曝光），避免和“变动”混淆。

## v7：复盘报告按“结论先行 + 复盘四步”重写

旧版报告是一份 Markdown 文字稿：维度少、全是文字，前面研究的趋势、活动、关键词、结构等维度没有进报告。v7 把 `#reports` 改成可阅读、可补充、可导出的报告文档。

### 写法依据（调研结论）

| 来源 | 用在报告里的做法 |
| --- | --- |
| 金字塔原理 / SCQA（McKinsey，Barbara Minto） | 结论先行：第 1 节一句话回答“好不好、为什么、下周先做什么”；每节标题是一句**结论**（如“销售额日均下降 21.5%，主要因为 CVR 从 13.0% 降到 9.8%”），不是“整体表现”这类主题名 |
| 联想复盘四步法、美军 AAR | 回顾目标 → 评估结果 → 分析原因 → 总结规律；左侧“报告结构”按 **结果 / 原因 / 行动 / 沉淀** 分组 |
| 亚马逊 WBR（Weekly Business Review） | 本期放进近 12 周里看（趋势背景）；连续 2 周同向才算趋势；只解释显著变化；区分可控动作（出价、否定、收割、预算）与结果指标 |
| PPC 代理商周报实践 | 先回看上期动作是否见效（闭环），再给下周动作清单（优先级、预计影响、负责人、复查日）；金额只用于排优先级 |
| 归因滞后（SP 7 天归因） | 封面标出“最近 3 天归因未补全”，附录说明 ACOS 偏高、销售偏低 |

### 交互

- 左侧 **报告结构**：按 结果 / 原因 / 行动 / 沉淀 分组的目录，带每节状态点（需处理 / 需关注 / 正常 / 参考），点击跳转，勾选决定报告和导出包含哪些章节；宽度 ≤ 1100px 时隐藏目录，报告历史变为横向卡片。
- 每节底部 **补充说明**：运营补充背景与判断（如“断货 2 天”），存于浏览器本地（`repNotes`），复制和导出 Markdown 时以引用块带上。
- **确认报告**：草稿 ↔ 已确认；保存到历史后正文按当时数据固定，下期“上期动作复盘”读取其中的动作清单。
- **复制正文 / 导出 Markdown**：`reportMd()` 按同一章节结构输出，图表转成表格。
- **AI（可选）** 只改写各节文字；章节结构、数字和图表仍由规则计算。

### 实现要点

- `repCtx()` 一次算好各节共用的数据（拆解、活动、变动、周期动作、结构、12 周序列）；每节函数返回 `{tone, title, body, md}`，HTML 与 Markdown 共用同一套数字。
- 金额统一换算成“每周”（天数不同时先按日均）；`prevCycle()` 也改为按日均比较，周期优化“准备与回看”同步显示“日均销售 / 日均花费”。
- 报告文档使用容器查询（`.rdoc` 的 `container-type: inline-size`），在 1440 / 1024 / 390 下分别排成 6 / 3 / 2 列指标卡。
