# 开品维度图谱规范

> 版本 v1.0 · 2026-11-06 · 样板品类：**水彩本**（`selection_map/data/dimension_atlas/book.json`，挂在 耗材 › 本册纸张 › 水彩纸）
>
> 所有产品品类今后都按本规范研究、登记、接入和展示。样板以外的品类与样板冲突时，以本规范为准；本规范没写到的，照水彩本的做法。
> 本规范不改变 `AGENTS.md` 的研究与证据规则（覆盖、核验、销量门槛、主数据唯一等），两者同时适用。

---

## 一、一个品类要交付什么

每个品类交付一份数据文件 `selection_map/data/dimension_atlas/<id>.json`（结构见交接包 `data/schema.ts`，字段说明见下表），再在 `selection_map/dimension_links.json` 里登记挂接位置和形态对应。

| 模块 | 内容 | 最低要求（水彩本的实际数量） |
|---|---|---|
| 品类信息 | `id`（英文、驼峰，永不改名）、`name`、`en`、`updated`（数据快照月份）；属于某个系列时加 `series` 和一句话定位 `pos` | 必填 |
| 品类范围 `scope` | 定义、纳入、不纳入、邻近品类、平台搜索关键词 | 五项都写 |
| 登记规则 `rules` | 本品类特有的登记口径（单位换算、易混淆概念怎么判、页面矛盾怎么记） | ≥ 6 条（8） |
| ② 分类维度 `dims` | 固定三组：**产品本体 / 销售形态 / 市场定位**；组下分维度类（A、B、C…），维度标 L1 定义品类 / L2 规格变体 / L3 卖点差异 / L0 合规门槛；每个维度给取值，难判断的写定义和判定规则 | ≥ 14 个维度（29） |
| ① 在售类型 `types` | 先按结构分组，再列类型。每个类型 20 个字段齐全：体量（主流 / 细分 / 小众）及依据、维度组合、代表品牌、价格带、人群、竞争、常见差评、依据来源、示意图、示例商品、对应维度（带来源标记）、优点、缺点、升级方向、判断、新品必须 / 加分 / 避免 | ≥ 5 个类型（10）；每个类型示例商品 ≥ 2 |
| ③ 缺口与机会 `opps` | 六项评分（需求 .25、竞争 .20、差异化 .15、供应链 .15、利润 .15、依据 .10），总分 ≥ 3.5 为 A、≥ 3.0 为 B、其余 C；证据不足记“线索”，核实后不成立记“已排除”并写排除原因；每个机会写对标的在售类型（`from`） | 打分机会 ≥ 2、线索 ≥ 1、已排除 ≥ 1（6 / 1 / 1） |
| ④ 白地图 `grids` | 4 张：两张“结构 × 结构”（本品类最关键的两组维度交叉）、一张“套装结构 / 形态 × 价格带”、一张“使用场景 × 关键卖点”。格子分开标供给（红海 R / 有供给 S / 稀少 L / 空白 E / 不成立 X）和需求（0–3） | 4 张（4） |
| 参考与来源 `refs` / `src` | 示例商品和格子链接用 `refs`，类型和机会的依据用 `src`；价格、评分、徽章都是 `updated` 当月的页面快照 | 引用的 key 必须存在 |

**命名即关联键**：类型名、维度名、机会名、白地图 id 一经接入不改名；确需改名时同步修改所有引用和 `dimension_links.json`，并在交付说明里写明。

## 二、研究流程

1. **定边界**：写品类定义、纳入、不纳入、邻近品类。
2. **采样**：美国站和国内平台各取畅销头部、白牌主力、品牌代表款、新上架款。
3. **拆维度**：按产品本体 / 销售形态 / 市场定位归类，同组内不重叠；标 L1 / L2 / L3 / L0。
4. **规范取值**：型号、标称规格、实测规格分开；未披露记“未披露”，页面前后矛盾记“页面矛盾”。
5. **归纳在售类型**：先按结构分组，再标体量；每个类型填满 20 个字段。
6. **画白地图**：4 张，供给和需求分开标；机会格必须同时满足“供给稀少或空白”和“需求 ≥ 2”。
7. **机会评分**：按六项评分卡打分；先核实再定级，不成立的移到“已排除”并写原因。
8. **接入地图**：在 `dimension_links.json` 登记挂接位置和形态对应（见第三节）。
9. **生成与校验**：运行 `python3 selection_map/build_dimension_data.py`，必须无错误。
10. **验收**：按第五节逐项检查，交付说明分开写“流程核验 / 真实数据核验 / 程序验证”。

## 三、接入选品地图

**挂接（`attach`）**：一个品类挂在地图分类树中“所有形态都属于本品类”的最高节点上，用形态字段匹配（`category` / `group` / `subcategory` / `product_type`，可写数组）。例：水彩本 `{"group":"本册纸张","product_type":"水彩纸"}`。一个品类可以挂多个节点（如画柜挂 画柜 / 画车 / 晾画架），一个节点只挂一个品类。

**形态对应（`records`）**：挂接节点下的每个地图形态，对应到一个**主**在售类型（数组第一个），可加相关类型。确实对应不上的不硬凑，留空即可：它会显示在“地图形态 · 未对应在售类型”，说明维度图谱需要补类型或地图分类需要复核。主归属在别的品类时写进 `cross`。

**不改主数据**：维度图谱是分类标准和市场类型研究，不是 `product_map.json` 的第二份主数据；接入不改任何形态的覆盖、规划、核验、初筛或研究结论。形态对应先标“初步对应，待人工确认”，确认后再去掉。

**生成物**：`web/dimension-data.js` 只由脚本生成，不手改。

## 四、展示形式（固定，所有品类相同）

### 4.1 思维导图
- 挂接节点（如“水彩纸”）的下一级固定为 **① 市场在售商品类型 / ② 分类维度 / ③ 缺口与开品机会 / ④ 白地图**，节点旁显示“开品维度图谱 · N 类型 · N 机会”。
- ① 下是类型分组 → 在售类型 → **地图形态（同一份记录，颜色仍表示美国站覆盖）**；没有对应形态的类型标“地图无形态”。
- 默认收起：挂接节点本身、② 分类维度、各维度类、④ 白地图、“已排除”分组。
- 点击规则：第一次点选中并展开，已选中时再点收起 / 展开。

### 4.2 详情面板（右侧，沿用原详情区）
- 挂接节点：品类总览（类型 / 维度 / 机会数、形态已对应数、品类范围、A / B 机会、地图无形态的类型、登记规则）。
- 在售类型：示意图、对应地图形态（可点开原形态详情）及其商品图、体量依据、代表商品、价格、人群、竞争、差评、维度组合、示例商品、对应维度（可跳转）、优缺点、升级方向与判断、新品属性清单、相关机会、依据。
- 机会：优先级、缺口类型、依据强度、缺口依据或排除原因、评分卡、维度组合、差异化、价格、风险、验证方法、对标类型、相关地图形态、来源。
- 维度 / 取值 / 白地图：定义、规则、取值、反查在售类型；白地图给汇总和“打开白地图”。

### 4.3 品类工作台（导图下方，全宽）
选中挂接节点、其下任一节点或其下的地图形态时出现。顶部：品类名、一句话定位、四个数字（在售类型、A / B 机会、地图形态已对应、类型地图无形态）。标签页固定为以下五个，顺序不变：

| 标签页 | 固定内容 |
|---|---|
| 在售类型 | 按分组的卡片墙；每张卡：示意图、体量 / 竞争 / 判断 / 价格、维度组合、地图形态编号（可点）或“地图无形态 · 可作规划空位”、优缺点各 2 条、常见差评、新品必须 / 避免、相关机会、判断说明；末尾列“地图形态 · 未对应在售类型” |
| 白地图 | 4 张切换、问题句、机会格 / 待验证汇总（可点）、整张表、格子详情（判断、1–3 个参考链接、京东参考、相关类型、关联机会）、全屏查看 |
| 开品机会 | 按 A / B / C / 线索 / 已排除排列的卡片：评分柱与总分、缺口依据或排除原因、维度组合、价格、差异化、风险、验证方法、对标类型、相关地图形态 |
| 分类维度 | 产品本体 / 销售形态 / 市场定位三栏；每个维度标 L 级和“已登记类型数 / 类型总数”，每个取值标使用它的类型数 |
| 类型对照 | 全部在售类型一张表：体量、维度组合、代表商品、价格、竞争、判断、地图形态、常见差评 |

同一视图有多个挂接点时（如 颜料 › 水彩 / 水粉 / 丙烯 / 油画），工作台顶部显示切换卡片：挂接节点名、品类名、一句话定位、前两个 A / B 机会。

### 4.4 联动
- 导图点类型 / 机会 / 维度 / 白地图 → 工作台切到对应标签页并高亮。
- 工作台点标题 → 导图定位该节点（展开祖先并居中）并打开详情。
- 任何地方点形态编号 → 打开原形态详情。
- 离线 HTML 快照（`build.py`）同样包含维度图谱，行为一致。

### 4.5 视觉
- 只用 `style.css` 的颜色 token；形态圆点颜色只表示美国站覆盖。
- 判断：可做 = 绿、谨慎 = 琥珀、不建议 = 灰；机会：A 红、B 琥珀、C 蓝灰、线索虚线、已排除灰。
- 示意图是结构示意，标“结构示意，不是实拍”；商品图只来自已匹配的地图形态，标“不证明与本类型同款”。

## 五、验收清单

**数据（脚本自动检查，有错误就不生成）**
- [ ] 品类信息、范围五项、规则 ≥ 6 条
- [ ] 维度三组齐全、L 级合法、每个维度有取值、维度 ≥ 14 个
- [ ] 类型 ≥ 5 个、字段齐全、示例商品 ≥ 2、对应维度名都存在、类型名不重复
- [ ] 打分机会 ≥ 2、线索 ≥ 1、已排除 ≥ 1；评分六项 1–5；已排除有原因；`from` 的类型都存在
- [ ] 白地图 4 张、每行格子数 = 列数、搜索词数 = 行数、价格带视图有价格区间、格子代码合法、格子引用的商品 / 类型 / 机会都存在
- [ ] `refs` / `src` 引用的 key 都存在
- [ ] `dimension_links.json` 的品类、形态编号、类型名都存在

**联动（本地程序人工检查）**
- [ ] 从导图逐级进入、从侧栏直接进入，挂接节点下都显示 ①②③④
- [ ] 地图形态挂在对应类型下，点开是原形态详情
- [ ] 工作台五个标签页都有内容；导图与工作台双向跳转正常
- [ ] 离线快照可展开；浏览器控制台无脚本错误
- [ ] `python3 -m unittest selection_map.test_server selection_map.test_map_sections selection_map.test_product_types` 通过

**交付说明**：写清新增 / 修改的品类、挂接位置、形态对应中待确认的条目、仍未覆盖的地图分类（见 `docs/开品维度图谱覆盖进度.md`，由脚本生成）。

## 六、新品类的最快做法

1. 复制 `book.json` 改写，或从交接包 `_template.js` 开始。
2. 在 `dimension_links.json` 加一条 `attach` 和本品类的形态对应。
3. 运行 `python3 selection_map/build_dimension_data.py`，按报错补齐。
4. 启动程序，按第五节检查。
