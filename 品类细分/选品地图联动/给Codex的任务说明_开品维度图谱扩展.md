## 4. 每个品类怎么做（按规范第二、三、六节）

1. **定边界**：品类定义 / 纳入 / 不纳入 / 邻近品类 / 平台关键词。
2. **真实调研**：美国站（Amazon 搜索页与商品页、品牌官网、评测、论坛）+ 国内平台（京东、淘宝、1688），覆盖畅销头部、白牌主力、品牌代表款、新上架款。
3. **写数据** `selection_map/data/dimension_atlas/<id>.json`：复制 `book.json` 改写。最低要求（括号内为水彩本）：
   - 登记规则 ≥ 6 条（8）
   - 分类维度三组 产品本体 / 销售形态 / 市场定位，≥ 14 个维度（29），标 L1 / L2 / L3 / L0
   - 在售类型 ≥ 5 个（10），每个 20 个字段齐全，示例商品 ≥ 2
   - 机会：打分 ≥ 2、线索 ≥ 1、已排除 ≥ 1（6 / 1 / 1），六项评分，已排除写原因
   - 白地图 4 张：两张结构 × 结构、一张 × 价格带、一张 使用场景 × 关键卖点
4. **接入**：在 `dimension_links.json` 加 `attach`（挂在“下面所有形态都属于本品类”的最高节点）和该节点下每个地图形态的主对应类型；对应不上的不硬凑。
5. **示意图**：`fig.k` 从 `web/dimension-figs.src.js` 已有图形里选；没有合适的就在该文件加一个分支，并在浏览器里看过。
6. **构建**：`python3 selection_map/build_dimension_data.py` 必须无错误（它按规范自动校验，不合格不生成）。
7. **验收**：按规范第五节逐项检查，并截图（导图展开挂接节点 + 工作台“在售类型”页 + “白地图”页）。

## 5. 证据与数据规则（必须）

- **不改 `product_map.json`**。维度图谱是分类标准和市场类型研究，不是第二份主数据；不得借此修改形态的覆盖、规划、核验、初筛或结论。
- 示例商品、格子链接必须是**实际存在**的页面；没核实到具体商品时用搜索页链接并写明“搜索页”，不编造 ASIN、价格、评分或销量。
- 价格、评分、徽章、“过去一个月购买”标签都是页面快照，记在品类 `updated` 月份下。体量依据可用徽章、购买量标签、在售款数等公开信号；**BSR、评论数、工具流量分不得当作销量**（`AGENTS.md` 第 5 条）。
- 页面前后矛盾记“页面矛盾”，未写记“未披露”；对应维度的取值标来源（厂家 / 卖家 / 评测 / 未披露 / 推断）。
- 机会必须先核实再定级；核实后不成立的移到“已排除”并保留原因，不删除。
- 形态对应标“初步对应，待人工确认”，在交付说明里列出。

## 6. 拆分原则与建议批次

**拆分原则**
- 一个维度图谱 = 一组共用分类维度的产品。核心维度不同的体系要拆开，用同一个 `series` 归组并各写一句 `pos`（参照颜料拆成水彩 / 水粉 / 丙烯 / 油画，画架拆成 7 个）。
- 一个品类至少要有 5 个市场在售类型；地图里太碎的小类（只有 1–2 个形态）合并成一个品类，在 ① 里按结构分组。
- 一个地图节点只挂一个品类；一个品类可以挂多个节点。
- id 用英文驼峰，一经接入不改名。
