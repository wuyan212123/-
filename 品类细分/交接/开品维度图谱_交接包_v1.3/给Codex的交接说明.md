## 1. 这是什么

一个按品类组织的开品研究页面。每个品类拆成三块，加四个辅助模块：

| 模块 | 作用 |
|---|---|
| ① 在售类型（已观察） | 市场上现在主要卖的商品类型。每个类型有 5 项：示例商品、对应分类维度（带来源标记）、优势与缺点、升级方向与机会判断、新品属性清单 |
| ② 分类维度 | 全部维度和取值，按“产品本体 / 销售形态 / 市场定位”三组，标 L1 / L2 / L3 / 门槛 |
| ③ 缺口与机会（假设） | 6 项评分算出 A / B / C；证据不足列为“线索”，核实后不成立列为“已排除”并保留原因 |
| 白地图 | 维度两两交叉，每格分开标“供给”和“需求”，格子里有 1–3 个参考链接 |
| 类型档案 | 每个类型一张卡（示意图、示例商品、优缺点、新品要求） |
| 对照表 / 机会评估 | 横向比较用的两张表 |
| 方法与规则 | 通用调研流程、登记规则、评分口径 + 本品类专用规则 |

**唯一可信源（source of truth）**：`src/categories/*.js`（数据）和 `src/engine/*`（行为与样式）。`reference/开品维度图谱.html` 是这两者构建出来的成品，用于对照；`reference/screenshots/` 用于视觉验收。

## 5. 数据结构要点（详见 `data/schema.ts`）

- 一个品类 = 一个 `Category` 对象。字段：`id / name / en / updated / series? / pos? / scope / rules / dims / types / opps / grids / refs / src`。`series`、`pos` 只有颜料系列 4 个、画架系列 7 个品类有，针管笔、水彩本没有这两个字段，迁移时不要补空值。
- **按名称引用**（迁移时这些名称必须保持一字不差，否则关联会断）：
  - `TypeItem.map[i][0]` → `Dimension.t`
  - `Opportunity.from`（多个用“、”分隔）→ `TypeItem.t`
  - `GridCell[2].t[]` → `TypeItem.t`；`GridCell[2].o` → `Opportunity.t`
- **按 key 引用**：`TypeItem.ex[i][0]`、`GridCell[2].r[]` → `refs`；`TypeItem.ev[]`、`Opportunity.ev[]` → `src`。
- `TypeItem.ex` 渲染前要展开：`[key, 快照说明]` → `{n: refs[key][0], u: refs[key][1], s: 快照说明}`；key 不存在时显示“（缺少参考商品 key）”。
- `Opportunity.total`、`Opportunity.pri` 是**计算字段**，不存数据，运行时算（导出 JSON 时也要剔除）。
- 如果入库到关系型数据库，建议保留一份原始 JSON 字段，保证可以原样导出、重新构建参考版本。

### 6.2 工具条与图例（文案照抄）
- 按钮：`① 在售类型`、`② 分类维度`、`③ 缺口机会`、`收起到默认`、`展开全部`、搜索框（占位 `搜索维度、类型、商品或机会`）、`复制大纲（可导入 XMind）`、`复制本品类数据（JSON）`。
- 图例：L1 定义品类 / L2 规格变体 / L3 卖点差异 / 门槛 合规门槛；主流 / 细分 / 小众 市场体量；竞争 高 / 中 / 低；可做 / 谨慎 / 不建议 类型判断；A / B / C / ? / × 机会：优先级 / 线索 / 已排除；属性来源：厂家 / 卖家 / 评测 / 未披露 / 推断。

### 6.3 计算规则（必须逐条一致）
**机会评分**

| 项 | key | 权重 | 口径 |
|---|---|---|---|
| 需求信号 | d | 0.25 | 搜索量、销量信号、人群规模。5 = 有明确强需求 |
| 竞争空间 | c | 0.20 | 5 = 几乎没有同类产品，1 = 红海 |
| 差异化可展示 | x | 0.15 | 卖点能否在主图 / 视频里一眼看懂 |
| 供应链可行 | s | 0.15 | 工厂能力、开模、品控难度。5 = 现成供应链 |
| 利润空间 | p | 0.15 | 建议售价与成本、广告费的差距 |
| 依据强度 | e | 0.10 | 5 = 有多个直接来源，1 = 纯推断 |

- `total = Σ(分数 × 权重)`，四舍五入到 2 位小数。
- `state === "clue"` → 优先级 `Q`（显示“?”）；`state === "out"` → `X`（显示“×”）；否则 `total ≥ 3.5` → A，`≥ 3.0` → B，其余 C。
- ③ 的分组顺序：`A 优先验证`、`B 次优先`、`C 先观察`、`线索（证据不足，待验证）`、`已排除（核实后不成立）`；组内按 total 降序；空组不显示。

**白地图格子分类**（代码 = 供给字母 + 需求数字）
- `low = 供给是 L 或 E`
- `clue = 选项 clue 为 true，或 (low 且 需求 = 0)`
- `opp（机会格）= low 且 需求 ≥ 2 且 不是 clue`
- 供给 X 的格子：斜纹底，不可点击，不显示需求和链接数。
- 格子显示：供给标签、`需求 ●●○`（需求 0 显示 `需求 ?`）、一句话（为“—”时不显示）、价位分布条（有 tier 时）、`N 个参考链接`、关联机会徽章（机会已排除时显示灰色“已排除：{名称}”；无关联机会但是 clue 时显示“新线索，待验证”）。

**格子参考链接（1–3 个）**
- 商品 = `r` 里的 key 解析出的 refs。
- 搜索词 `q` = `k[0]`；没有 `k` 时 = `rk[行]` + 空格 + `ck[列]`（价格带视图不拼 ck）。
- Amazon 搜索链接 = `https://www.amazon.com/s?k={encodeURIComponent(q)}`，价格带视图追加 `&rh=p_36%3A{price[列]}`；链接名称在价格带视图后缀“（{列名}）”。
- 供给为 L / E：前 2 个商品 + 1 个搜索链接；否则商品 ≥ 3 时取前 3 个，不足 3 个时全部商品 + 1 个搜索链接。
- 京东参考：`rc[行]` + 空格 + `cc[列]`（为空则不显示），链接 `https://search.jd.com/Search?keyword={encodeURIComponent}&enc=utf-8`。

**汇总条**：`{n} 个机会格`、`{n} 个待验证`、`{红海} 红海 · {有供给} 有供给 · {稀少} 稀少 · {空白} 空白 · {不成立} 不成立`；下方列出机会格（实线绿框）和待验证格（虚线橙框）的芯片，芯片后缀“→ A/B/C/线索”（关联机会为已排除时不显示后缀）。

### 6.4 思维导图
- 根节点 = 品类；第一层 3 个分区：`① 市场在售商品类型`、`② 分类维度`、`③ 缺口与开品机会`，分区副标题见 `app.js` 的 `build()`。
- 层级：分区 → 分组（虚线框）→（① 类型卡片 → 5 张信息卡）/（② 维度类 → 维度 → 取值）/（③ 机会卡片）。
- 节点宽度：根 160、分区 190、分组 170、维度类 ≥140 不换行、维度 ≤250、取值 ≤320、类型 / 机会卡 360、信息卡 420（px）。
- 布局：水平树；子节点 x = 父 x + 父宽 + 间距（根 56、分区 48、其余 40）；叶子纵向依次排列，纵向间距按角色（分区 28、分组 16、维度类 12、类型 12、机会 10、维度 8、信息卡 10、其余 4），分区结束后额外 +24，分组 / 维度类 / 类型结束后 +8；父节点纵向居中于首尾子节点；连线是三次贝塞尔曲线，颜色继承分支色；已排除机会的连线为虚线。
- 默认折叠：所有维度类、所有类型、“已排除”分组。`收起到默认` 恢复此状态；`展开全部` 全展开。
- 加载后和切换品类后：画布滚动到根节点垂直居中。
- 缩放 40%–160%，步进 10%，中间按钮显示当前百分比，点击回到 100%。
- 搜索：输入 180ms 防抖；匹配类型 / 维度 / 取值 / 机会 / 示例商品名（不区分大小写），命中节点高亮并自动展开祖先，滚动到第一个命中。
- 点击有子节点的节点切换展开 / 折叠；点击信息卡不折叠；信息卡里“对应分类维度”的维度名可点，跳到 ② 中对应维度并展开。
- 键盘：节点可 Tab 聚焦，Enter / 空格等同点击。

### 6.5 详情面板（右侧，吸顶，按节点角色显示）
- **根**：品类定义、纳入、不纳入、邻近品类、平台搜索关键词、“怎么读这张图”。
- **类型**：标题、体量 + 竞争说明 + 判断、体量依据、维度组合、代表品牌 / 商品、价格带、主力人群与场景、常见差评、5 项内容（同信息卡）、相关开品机会（from 包含该类型名的机会）、依据（evl + src 链接）。
- **机会**：标题、优先级 + 缺口类型 + 依据强度；已排除先显示“排除原因”，再显示“最初的判断”；评分卡（6 条进度条 + 总分 + 优先级）；维度组合、差异化、建议价格、对标的在售类型、风险、验证方法、来源。
- **维度**：定义、判定 / 登记规则、取值、“在售类型在这个维度上的取值”（反查所有类型的 map，带来源标记）、关键词。

### 6.12 视觉与响应式
- 颜色全部用 `page.html` 里 `:root` 的 token；暗色主题在 `@media (prefers-color-scheme: dark)`（排除 `[data-theme="light"]`）和 `[data-theme="dark"]` 两处重新定义，必须保留这三态逻辑。
- 字体：标题 Noto Serif SC，正文 Noto Sans SC，数字 / 代码 IBM Plex Mono。
- 断点：≤ 980px 详情面板移到画布下方且取消吸顶；≤ 600px 优缺点、新品清单变单列。
- 页面在 390px 宽度下不得出现横向滚动（表格和画布在各自容器内滚动）。
- ≤ 640px 时系列总览卡片改为容器内横向滑动（每张卡宽 78%，scroll-snap），不再纵向堆叠。
- ≤ 640px 时品类标签（`#cat-tabs`）改为单行横向滑动（隐藏滚动条），每次渲染后把当前品类按钮滚到可见区域中间（v1.3）。
- 吸顶导航高度实时写入 `--nav-h`，用于章节锚点偏移和详情面板吸顶位置。
- `prefers-reduced-motion` 下关闭平滑滚动和过渡。

### 6.13 品类定位与状态
- 当前品类存在 `localStorage("mm-tab")`（读写都要 try/catch）。接入选品地图后，**从选品地图进入时要能直接定位到指定品类**（例如 URL 参数或路由参数 `?cat=oil`），优先级高于 localStorage。这是唯一需要新增的行为。
- 只有一个品类时隐藏品类切换（v1.1）。

### 6.14 系列（v1.2 新增，细节以 `app.js` 的 `renderChrome()`、`renderSeries()` 为准）
- 品类可选字段 `series`（如 `"颜料"`、`"画架"`）、`pos`（一句话定位）。CATS 顺序：pen、book、wc、gouache、acrylic、oil、easelFloor、easelTable、easelPlein、easelKids、easelDisplay、artBox、artCabinet（`build.py` 的 `ORDER`）。

- 系列总览（`#seriesbox`，位于导图标题和范围卡之间）：当前品类没有 `series` 时隐藏；有时显示标题 `{系列}系列总览`、副标题 `{n} 个体系，分别独立研究；点卡片切换`，每个同系列品类一张卡片：名称、`pos`、`{类型数} 个类型 · {维度数} 个维度 · {机会数} 个机会假设`、该品类 A / B 级机会按总分降序最多 3 条（带优先级徽章）。当前品类卡片加粗边框；点卡片 = 切换到该品类。

- 不要把 `id`（pen / book / wc / gouache / acrylic / oil / easelFloor / easelTable / easelPlein / easelKids / easelDisplay / artBox / artCabinet）、`series` 值、类型名、维度名、机会名改名——它们是关联键。
- 不要在未确认的情况下改变选品地图现有页面的行为。

## 10. 以后新增品类

保持“引擎 + 品类数据”分离：新增品类只新增一份数据（参照 `src/categories/_template.js` 的注释或 `data/schema.ts`），不改引擎。一个大品类下面有几个体系、各自需要独立研究时（如颜料 → 水彩 / 水粉 / 丙烯 / 油画），每个体系建成一个独立品类，用相同的 `series` 归组，并各写一句 `pos`；不要把几个体系塞进一个品类。新增后必须通过 §8.6 的校验。

## 11. 已知限制（不是 bug，不要“修”）

- 价格、评分、徽章是 2026-11 的页面快照，以链接实时页面为准。
- 需求信号和机会评分是根据公开信息的判断分，尚未接入实时销量数据。
- 少数品牌官网链接标注了“参考文件提供”，表示未逐一打开核实。
- 部分商品页面本身有规格矛盾（例如冷压 / 热压），数据里已按“页面矛盾 / 未披露”记录，这是有意为之。
