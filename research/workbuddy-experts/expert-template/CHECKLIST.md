# 专家上架前自检清单（由头部专家反推）

## 卡片层（plugin.json）
- [ ] `displayName` 起一个好记的中文名（参考：文爆爆、卖得好、钱守通、严守约）
- [ ] `displayDescription` 写**结果**而不是能力：“上传 X，N 分钟拿到 Y”
- [ ] `defaultInitPrompt`：用户照着就能直接发、不用改的一句话
- [ ] 3 个 `quickPrompts`：最常见、最惊艳、最具体的场景各一个，都写明交付物
- [ ] 3 个 `tags`，选对 `categoryId`，`zh` 和 `en` 两种语言都填

## 提示词层（agents/*.md）
- [ ] frontmatter 的 `description` 写满触发词（用户会怎么说）
- [ ] 一句反常识定位 + 一张“痛点 / 以前的做法 / 我做的事”表
- [ ] 编号工作流，每一步写清输入和输出
- [ ] Step 0：只问 2–4 件事，每件都有默认值；“已经说过的不要重复问”
- [ ] 交付物具体到文件名、存放路径和 Markdown 模板（TL;DR → 正文 → 行动清单 → 风险与假设）
- [ ] “必须调用技能，禁止凭训练数据或肉眼估算”
- [ ] 降级：缺数据怎么办、外部服务不可用怎么办、超长输入怎么办
- [ ] 边界：明确不做的事，以及应该转给谁（其他专家或真人服务）
- [ ] 交付前自检 3–5 条
- [ ] 不写空泛的 Success Metrics（如“提升 300% 线索”），不堆能力清单

## 技能层（skills/）
- [ ] 确定性工作（计算、格式、文件读写）放进 `scripts/`，**包里真的带上代码**
- [ ] 长方法论放 `references/`，在 SKILL.md 里写清什么时候加载
- [ ] 不在包里硬编码 API Key 或 Token

## 质量层
- [ ] 5–8 条 golden 测试题，覆盖正常流程、缺数据、越界请求和风格要求
- [ ] 能机器判断的风格规则写成 rubric（禁用词、字数、问号数、必须表态）
- [ ] 每次改提示词都回归一遍，并记录 baseline

## 专家团（只在任务能拆成并行视角时才做）
- [ ] 成员按“视角”拆，不按“工种”拆；建议 3–5 人
- [ ] 主理人铁律：只编排、不代写；信息流全部经主理人中转；不许跳阶段
- [ ] 每个预设工作流标明串行还是并行，并配统一的最终交付模板
