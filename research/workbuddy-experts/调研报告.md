# WorkBuddy 头部专家拆解与编写方法论（调研报告）

> 调研日期：2026-10-15 ｜ 数据快照：WorkBuddy 公开专家市场 2026-10-09 同步版（429 个专家包）
> 目的：搞清楚排在前面、被平台推荐的专家是怎么写的，实测它们的输出，反推出可复用的编写方法，为后续自己上架专家做准备。

---

## 0. 结论速览

1. **头部专家不是“人设 + 能力清单”，而是“一条可执行的 SOP”。** 28 个被平台放到精选位/打上「特邀专家」标签的专家，100% 写了工作流，96% 写了交付物规范，86% 写了禁止项/边界。直接从英文模板改编来的 168 个专家，这三项只有 79% / 7% / 6%。
2. **“模型做判断，代码做操作”是最硬的护城河。** 好的专家只让模型输出结构化判断（JSON/卡片），格式、计算、文件写入交给 `skills/` 里的脚本。实测花叔审稿专家，这套设计在 6 个预埋问题上 6/6 命中，失配条目被单独隔离，原文件没被改动。
3. **人格要“可校验”，不能只“可描述”。** AI 刘小排把语气写成了 14 条能机器勾选的 rubric：禁忌词、问号数量、金句次数、字数区间、必须五选一表态。还自带回归测试脚本，每次改提示词都重跑一遍。
4. **第一屏决定转化。** `defaultInitPrompt` 和 `quickPrompts` 是用户最先点的按钮。官方自己写的推荐 query 有固定套路：写明交付物 + 开工前最多问几件事 + 没说明时用什么默认值 + 不许编造。
5. **专家团只在任务能拆成并行视角时才值得做。** 头部的专家团都写了“铁律 / 红线”，强制主理人走 TeamCreate → 派单 → 中转 → 汇编，禁止主理人自己代写成员的产出。
6. **机会点：** 市场里有 Listing 优化、通用 PPC，还有一个跨平台直接改广告的「广告投放操盘专家」，但没有专门做“亚马逊 SP 广告周度复盘”的专家。仓库里现成的《SP广告周度分析助手》可以直接改造成第一个专家（模板见 `expert-template/`）。

## 2. 专家包长什么样（平台机制）

### 2.1 目录结构（市场包实际结构）

```text
<plugin-name>/
├── .codebuddy-plugin/plugin.json   # 必需：市场卡片 + 组装清单
├── agents/<agent-name>.md          # 必需：系统提示词（专家团有多份）
├── skills/<skill>/SKILL.md         # 可选（68% 的头部专家有）：方法论 / 脚本 / 参考资料
│   ├── scripts/                    # 可选：确定性的计算、文件操作
│   └── references/                 # 可选：按需加载的长资料
├── avatars/*.png                   # 头像
├── settings.json                   # 少数有：{"agent": "<默认 agent>"}
└── README.md
```

### 2.2 plugin.json 关键字段（429 个包的出现频次）

| 字段 | 出现率 | 作用 |
|---|---|---|
| name / version / description / expertType / agentName / agents | ~100% | 组装：`expertType` 取 `agent` 或 `team` |
| displayName / profession / displayDescription | 96% | 卡片三件套：名字、职业、一句话卖点（中英双语） |
| avatar / categoryId | 96% | 头像、15 个分类之一 |
| defaultInitPrompt / quickPrompts / tags | 93–96% | **第一屏按钮**：默认问题 + 3 个快捷问题 + 3 个标签 |
| skills | 66% | 挂载的技能目录 |
| author | 64% | 署名，特邀专家几乎都有 |
| teamInfo / members | 53 个专家团 | `leadAgent` + `memberAgents`，每个成员单独配名字、职业、头像 |

### 2.3 agent.md frontmatter

最常见的字段是 `name`、`description`、`maxTurns`、`displayName`、`profession`，其次是 `skills`、`color`、`emoji`、`vibe`。`description` 的写法会影响能否被路由到：头部专家都把触发词写进去了，比如 aihot 写的是“当用户提到 AI 资讯、AI 日报、AI 热点……时激活”。`maxTurns`：单专家常设 30–80，专家团主理人设 200。

### 2.4 分类分布（找蓝海用）

内容创作 47 · 技术工程 44 · 数据智能 43 · 金融投资 39 · 营销增长 37 · 行业顾问 35 · 法务安全 27 · 腾讯专区 26 · 游戏空间 25 · 项目质量 23 · 全球发展 21 · 产品设计 19 · **销售商务 17 · 运营人力 15 · 开学季 11**（后三类最少）

官方推荐 query 池（运营侧的“核心场景运营池”）里，金融占比最高（12.4%）；快捷入口里“创作文档”和“深度研究”各占 19.1%。这些是平台主动导流的方向。

### 2.5 上架路径（来自官方文档摘要和社区文章）

- 客户端「我的专家 → 创建专家」做出来的专家只给自己或团队用。分享链接**不会上架市场**。
- 要上架市场，需要按规范打专家包，到开放平台（2026-09-02 上线）提交。流程：注册入驻 → 资质认证（建议企业认证）→ 完善信息 → 测试调试 → 提交审核 → 发布。社区反馈审核约 7 个工作日。
- 客户端内置 `expert-manager` 技能，可以按 plugin.json、Agent MD、头像三类规范生成专家包。长文档专家 README 里写的兼容目标是“WorkBuddy 5.3.14 / expert-manager 规范 v2.0”。

## 3. 头部专家拆解

| 专家 | 类型 / 运营位 | 规模 | 核心写法 | 最值得学的一点 |
|---|---|---|---|---|
| **AI 刘小排**（产品顾问） | 单专家 · 特邀 | agent 2.2KB + skill 37KB + 6 篇方法论 + 回归测试 | agent 只做路由，人格、方法、风格全部放进 skill | 人格量化：五选一结论、3 个必问、7 个回答 pattern、禁用词表、14 条 rubric 回归测试 |
| **花叔文档审稿专家** | 单专家 · 特邀 | agent 5.7KB，无脚本 | 3 种模式 × 关注点清单 + 5 步流程 + 3 层失败保护 | 定位反常识：“我不替你重写文档”，交付的是带修订痕迹的原 docx |
| **资讯速递（数字生命卡兹克）** | 单专家 · 特邀 · 精选位 6 | agent 3KB + skill（真实 API） | 意图→工作流路由表 + 输出规范（HTML 优先、Markdown 兜底） | 硬约束“必须调用技能，不得凭训练数据猜”，再配上数据源 |
| **美团生活助手** | 单专家 · 精选位 1 | agent 36KB | Step 0–B3 完整状态机：登录 → 意图 → 子流程 A/B，每个场景配展示模板 | 交易型专家要把每个分支和异常都写成模板 |
| **长文档写作与改稿（福帮手）** | 单专家 · 精选位 10 | agent 11KB + 150+ 文件 | 21 个场景 + 续接胶囊 + 证据状态 + 降级策略 | 跨会话续写：用“续接胶囊”保存上下文 |
| **MAI 并购交易 Agent** | 单专家 · 精选位 4 | agent 15KB | 首次问候 → 能做 / 不能做 → 三阶段工作流 → `[ESCALATE]` 转人工卡片 | 专业服务型专家把“转人工”设计成商业漏斗 |
| **小企业经营团队** | 专家团 · 官方 | 5 个 agent，共 21KB | 成员表 + 4 条正向规则 + 5 条红线 + 4 个预设工作流 + 统一交付模板 | 团队铁律：主理人只编排、不代写，所有信息流经主理人中转 |
| **花叔数据分析专家团** | 专家团 · 特邀 | 4 个 agent，共 18KB | 先问 3 件事 → 3 个视角并行 → 交叉印证 → HTML/XLSX/PPTX | 成员按“分析视角”拆，不按“工种”拆，并行才有意义 |
| **文爆爆**（内容创作，官方基础款） | 单专家 · 基础库 | agent 5.8KB + 5 个 skill | 英文模板：身份指令 + 能力清单 + Success Metrics | 反面参照：没有流程、没有交付规范，输出很依赖用户怎么问 |

### 3.1 典型骨架对比

**头部专家（以花叔审稿为例）**

```text
角色定位（一句反常识的定位）
→ 我解决的 N 个痛点（表格：传统做法 vs 我做的事）
→ 模式 / 场景（每种模式：适用对象 + 关注点清单）
→ 标准工作流（编号步骤，写清输入和输出）
→ 输出规范（交付文件名 + 摘要模板）
→ 失败保护 / 降级
→ 注意事项（边界、隐私、格式限制）
→ 核心信念（一句话，强化人设）
```

**基础款（以文爆爆为例）**

```text
CRITICAL IDENTITY DIRECTIVE（防止被问出底层模型）
→ Role Definition → Core Capabilities（8 条）→ Specialized Skills
→ Decision Framework（什么时候用我）→ Success Metrics（25% 互动率……）
→ 内置 Skill 使用场景 → Final Identity Reminder
```

基础款写的是“我会什么”，头部专家写的是“我会怎么做、交付什么、什么情况下不做”。

## 4. 量化对比：头部专家和普通专家差在哪

基于全部 429 个专家的 agent.md 正文，用关键词规则做的启发式统计（只用来看方向，不是精确值）：

| 组 | 数量 | 有工作流 | 有交付规范 | 有边界/禁止 | 先问再做 | 有降级 | 有自检 | 产出文件 | 挂 skill | 带脚本 | 专家团 | 有署名 | 提示词中位字数 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| **A 精选/特邀** | 28 | **100%** | **96%** | 86% | **61%** | **61%** | 39% | **50%** | 68% | 32% | **46%** | 86% | 9,654 |
| B 中文原生 | 233 | 94% | 83% | 85% | 50% | 43% | 33% | 26% | 77% | 42% | 15% | 75% | 4,506 |
| C 英文模板改编 | 168 | 79% | 7% | 6% | 2% | 14% | 15% | 9% | 52% | 29% | 2% | 6% | 11,534 |

几点解读：

- C 组提示词最长（中位 1.1 万字），但几乎没有交付规范和边界。**长度不等于质量，约束才等于质量。**
- A 组和 B 组拉开差距的地方在“先问再做 / 降级 / 产出文件 / 专家团”。头部专家更像一个能交付文件的工作流，而不是一个陪聊角色。
- A 组 46% 是专家团，比 B 组高 3 倍。平台在精选位上偏好“一句话拿到完整交付”的团队型产品。

## 5. 实测

> 测试限制：本环境网络屏蔽了 workbuddy.cn、腾讯云以及第三方 API，没法在 WorkBuddy 客户端里真机调用。所以采取两种方式：一是把专家包里描述的流程在本地完整复现；二是严格按专家提示词作答，再用专家包**自带的评分标准**判分。所有过程文件都在 `tests/` 下，可以复跑。

### 测试 1：花叔文档审稿专家（流程复现，全量通过）

- **输入：** 自制《软件开发服务合同》，预埋 6 个问题：金额没写含税口径、“尽快付款”、SLA 没量化、保密条款缺期限、管辖法院不明、“根据”应为“依据”。另加 1 条故意失配的决策，用来测失败隔离。
- **过程：** 模型只输出 `decisions.json`（结构化决策），由 `inject_review.py` 按专家描述的三层保护写入 OOXML。
- **结果：** 6/6 命中；生成 5 条批注、5 处修订（红色删除线 + 新文字）；失配条目被记录为 `SKIP-nomatch`，没有影响其他条目；原文件没被改动；Word 和 LibreOffice 都能正常打开。截图见 `tests/huashu-doc-reviewer/preview-1.png`。
- **发现的问题：**
  1. **包里没带任何脚本。** 提示词里描述的“代码注入”，实际要宿主模型每次现场写约 110 行 OOXML 代码。换成弱一点的模型，很可能就跑不起来了。**带上脚本**是这个专家最大的改进空间。
  2. 按段落输出 JSON 的设计**表达不了“缺失条款”**，比如合同里没有知识产权、验收条款。建议加一种“全文级问题”的批注类型。

### 测试 2：AI 刘小排（按包内 rubric 回归）

包里只跑过 T1（共 8 题）。本次补跑了 T2（B2B 决策链）和 T6（定价焦虑）。

| 题 | 机械可判项（r3/r4/r7/r10/r12/r13/r14） | 语义项（人工判） | 结论 |
|---|---|---|---|
| T1（包内原始记录） | 7/7 PASS | 作者记录 12 pass / 0 fail | ✅ |
| T2 B2B | 7/7 PASS（442 字，问号 3 个，金句 1 次） | r1 表态“需要砍小” ✅；r2 要求具体人名 ✅；r8 触发 4 角色 ✅；r11 引用方法论 ✅ | ✅ |
| T6 定价 | 7/7 PASS（375 字，问号 1 个） | 低价订阅陷阱 ✅；先一次性付费验证 ✅；购买理由四维度 ✅；“不直接给定价数字”只部分满足（给了 19.9 元作为验证价）⚠️ | ✅（1 处小偏差） |

- **结论：** 提示词约束足够具体，按它作答很容易拿到稳定、可复现的风格；14 条 rubric 本身也是很好的质检工具。
- **偏差说明：** 作答和判分都由同一个模型完成，结果是上限估计。包内 T1 的作者原始记录（GPT-5.5 作答 + 独立 judge）可以作为第三方参照。

### 测试 3：静态审查（真机条件不足的专家）

| 专家 | 发现 |
|---|---|
| 资讯速递 aihot | 意图路由、HTML/Markdown 双输出、日报 404 自动回退昨日、空结果提示都写了。**没写“API 不可达 / 被网络拦截”时怎么办。** 本环境实测 API 被代理拦截（403），这时专家既不能调用 API，又被禁止凭记忆回答，需要补一句兜底话术。 |
| 小企业经营团队 | 铁律、红线、预设工作流、落盘路径、统一收口模板都很完整，可以直接当专家团模板用。依赖宿主的 TeamCreate / SendMessage，离开 WorkBuddy 没法复现。 |
| 文爆爆（基础款） | 没有交付规范，也没有“先问什么”。快捷问题“撰写一篇品牌故事型深度长文”缺少品牌信息时，专家没有规定要先追问，输出质量完全看模型自己发挥。 |

## 6. 反推：受欢迎专家的编写方法（10 条）

1. **一句话定位要反常识、能落地。** 比如“我不替你重写文档”“先表态，再追问”。卡片上的 `displayDescription` 写清结果，不写能力，例如“一句话查到每天精选的 AI 动态，自动整理成中文简报，免配置免登录”。
2. **结构用 SOP，不用简历。** 骨架是：角色定位 → 场景/模式 → 编号工作流 → 交付规范 → 降级 → 边界。每一步写清输入和输出。
3. **开工前只问关键的 2–4 件事，并给默认值。** 学官方 query 写法：“先只问我四件事……我已经说过的不要重复问”“未说明时按 X 处理”。
4. **交付物要具体到文件名和模板。** 例如 `<原名>.reviewed.docx`、`ai-hot-briefing-{日期}.html`、`deliverables/smb-ops/<类型>-<主题>-<日期>.md`，再配上 TL;DR 和行动清单的固定结构。
5. **模型判断，代码执行。** 计算、格式、文件读写放进 `skills/<x>/scripts/`，提示词只要求模型输出结构化决策。专家包里**要真的带上脚本**。
6. **把“必须调用技能，禁止凭训练数据回答”写成硬约束。** 时效性、数据类专家必须写，同时写好数据源不可用时的兜底话术。
7. **风格要能校验。** 给出禁用词表、禁用的固定小标题、字数区间、问号上限、结论必须 N 选一，再配几条 golden 测试题做回归。
8. **降级和失败隔离写进提示词。** 日报 404 回退昨日；单条失败跳过并记录；超过 1 万字分段处理。
9. **边界和转人工也是产品的一部分。** 写清“能做 / 不能做”，用 `[ESCALATE]` 卡片把超出范围的需求导到真人服务。特邀专家普遍借此给作者自己的业务引流。
10. **第一屏营销：** 起一个好记的中文名（文爆爆、卖得好、钱守通、严守约），做 3 个快捷问题，分别覆盖“最常见 / 最惊艳 / 最具体”的场景。`description` 里堆够触发词，保证能被路由到。

**专家团额外 3 条：** ① 只在任务能拆成并行视角时才用；② 写铁律：主理人只编排、不代写，不许成员直连，不许跳阶段；③ 给每个预设工作流写明串行还是并行，以及统一的最终交付模板。

## 7. 下一步建议

1. **第一个专家：「亚马逊 SP 广告周度复盘师」。** 现有的 Streamlit 工具已经把清洗、对比、打标签、建议、导出 Excel 这些确定性逻辑写好了，正好符合“代码执行”这一层。改造方法：把 `core/` 放进 `skills/sp-ads-weekly-analysis/scripts/`，让 agent 负责“先问 4 件事 → 跑脚本 → 解读 → 交付 Excel 和周报”。草稿见 `expert-template/`。
2. 上架前，用 `expert-template/CHECKLIST.md` 自查，并写 5–8 条 golden 测试题（模仿刘小排的 `voice-tests/`），每次改提示词都回归一遍。
3. 有了单专家的使用数据之后，再考虑升级成“广告诊断 + Listing + 竞品词”专家团。
